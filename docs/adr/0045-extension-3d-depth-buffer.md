# ADR-0045: 3차원 장면은 삼각형 묶음 하나로 모양 목록에 넣고, 깊이 버퍼로 픽셀마다 빛을 주어 그린다

- 상태: Proposed
- 날짜: 2026-10-23
- 관련: ADR-0026(3차원 장면, 화가 알고리즘 부분을 대체), ADR-0042(vello_cpu로 그리기) · `src/extension/scene.rs`, `src/extension/raster3d.rs`, `src/extension/render.rs`, `src/extension/svg.rs`, `src/export/pdf.rs`, `resources/skills/extension/references/draw-3d.md`

## 배경 (Context)

ADR-0026의 장면은 면마다 평균 깊이로 줄 세워(화가 알고리즘) 2차원 다각형으로 넣었다. 서로 뚫는 면이나 큰 면 옆의 작은 면은 순서가
틀렸고, 면 하나가 모양 하나라 애니메이션 상한(2천)이 장면 크기를 정했고, 평면 음영뿐이었고, 이웃 면 틈을 0.35만큼 넓혀 가렸다.
ADR-0042로 그리기가 CPU 픽셀이 되면서 깊이 버퍼를 쓸 수 있게 됐다.

## 결정 (Decision)

**`scene:draw()`는 투영을 마친 삼각형 묶음(`raster3d::Mesh`)을 `Shape::Scene3D` 하나로 넣고, 그리는 쪽이 장면 칸을 깊이 버퍼로 그린다.**

- 묶음: 꼭짓점마다 캔버스 좌표(2차원 변환까지), 원근 보간 무게 `w`(원근 1/깊이, 직교 1), 깊이 비교 값(클수록 가깝다), 법선. 삼각형마다 색과
  빛을 받는지(면) 여부. 장면 칸의 네 꼭짓점(자르기)과 빛·주변광. 앞쪽 자르기(near)는 투영 전에 하고 법선도 보간한다.
- 그리기(`raster3d::rasterize`): 2×2 슈퍼샘플링(샘플 400만 개까지), 위·왼쪽 변 규칙. 불투명한 것을 먼저 깊이 버퍼로, 반투명한 것은 먼 것부터
  섞는다(깊이는 보되 쓰지 않는다). 빛은 픽셀마다 주변광 + 램버트이고 법선은 원근에 맞게 보간한다. 결과는 장면 칸 크기의 그림이고, `render`가
  자르기 경로 안에 그림으로 그린다(효과·섞기도 걸린다).
- 곡면(구·원기둥·원뿔·고리)은 꼭짓점 법선으로 부드럽게 칠한다. `scene:setShading("flat")`이면 면마다 한 색이다. 법선은 변환의 역전치로 옮긴다.
- 선(`scene:line`, `"line"` 면)은 화면에서 굵기만큼의 사각형으로 만들어 빛 없이 깊이를 보며 그린다(같은 깊이의 면보다 조금 앞).
- 내보내기: PDF는 장면 칸을 캔버스의 4배 PNG로, SVG(ePub)는 3배 PNG로 넣는다.

## 결과 (Consequences)

- (+): 서로 뚫는 물체, 바닥 위 물체의 가림이 맞다. 틈 땜질이 없다. 곡면이 부드럽다. 반투명이 뒤를 비춘다.
- (+): 장면이 모양 하나라 애니메이션 모양 상한에 걸리지 않는다(장면의 면은 2만 개까지).
- (-): 비용은 면 수보다 장면이 덮는 넓이를 따른다. 960×600px(2배) 장면 한 프레임이 Lua 포함 약 11ms다(release). UI 스레드에서 그린다.
- (-): PDF·ePub에서 3차원은 벡터가 아니다.
- (-): 같은 자리의 두 면은 깜박인다(깊이 버퍼의 한계). 닫힌 입체의 뒷면은 버리므로 반투명 입체는 앞면만 보인다. 선 끝은 모나다(둥근 끝 없음).
- 후속(TODO): 그리기를 작업 스레드로, 물체끼리 드리우는 그림자, 하이라이트(반사광).

## 대안 (Alternatives)

| 대안 | 기각 사유 |
| --- | --- |
| 화가 알고리즘에 BSP·면 쪼개기 | 순서는 맞아도 모양 수가 늘고, 부드러운 음영·반투명 정렬은 여전히 어렵다 |
| wgpu로 화면 밖에 그려 읽어 오기 | GPUI와 장치를 함께 쓰지 못해 읽어 와야 하고, 의존성과 셰이더 관리가 무겁다. 원고 블록 규모에는 CPU로 충분하다 |
| `euc` 등 소프트웨어 렌더러 크레이트 | 필요한 것(깊이·보간·슈퍼샘플링)이 작아 직접 쓰는 편이 모양 목록과 맞추기 쉽다 |
