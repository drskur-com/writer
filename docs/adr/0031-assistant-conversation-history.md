# ADR-0031: 어시스턴트 대화 기록은 라이브러리마다 하나로 모아 redb에 두고, 말마다 그때 열린 시트를 적는다

- 상태: Proposed
- 날짜: 2026-10-23
- 관련: ADR-0024(로컬 캐시 redb), ADR-0028(web_fetch 허락), ADR-0029(확장 초안) · `src/agent/history.rs`(`History`, `Summary`), `src/agent/mod.rs`(`Turn::sheet`, `request_turns`), `src/app/assistant_panel.rs`

## 배경 (Context)

어시스턴트 대화가 패널을 닫거나 앱을 끝내면 사라진다. 지난 대화를 다시 보고 이어 가고 싶다.

- 에이전트는 열린 시트만이 아니라 라이브러리 전체(다른 시트, 새 시트, 확장, 스킬)를 다룬다. "원고 전체에서 인물
  이름 점검"처럼 한 시트에 속하지 않는 대화가 있다.
- 대화 하나는 이미 시트를 넘나든다. 대화 상태는 앱에 있고, 시스템 프롬프트는 요청마다 그때 열린 시트로 만든다.
- 시트는 옮기고(ADR-0019·0020), 이름을 바꾸고, 지운다.
- 대화는 원문에서 다시 만들 수 없다. 반면 ADR-0024의 `cache.redb`는 깨지거나 형식이 바뀌면 지우고 새로 만든다.

## 결정 (Decision)

**대화 기록은 라이브러리마다 하나의 목록이다. 말마다 그때 열린 시트를 적어 두고, 기록 화면에서 "이 시트"로 거른다.
저장은 캐시와 따로 둔 redb 파일에 한다.**

- 위치: `<data_dir>/Writer/<라이브러리 경로 FNV-1a 해시>/conversations.redb`(macOS `~/Library/Application Support`).
  라이브러리 밖이라 동기화되지 않고, 에이전트의 파일 도구도 닿지 않는다. 키는 `cache::library_key`를 같이 쓴다.
- 열지 못하면(깨짐, 다른 창이 열었음) 파일을 지우지 않는다. 한 번 알리고 기록 없이 대화한다.
- 테이블:

| 테이블 | 키 | 값 |
| --- | --- | --- |
| `conversations` | 대화 id(`u64`, 만든 때 유닉스 밀리초, 겹치면 +1) | 요약 JSON: 제목(첫 사용자 말 첫 줄), 미리보기(마지막 말 첫 줄), 만든·마지막 시각, 시트들, 허락한 사이트 |
| `turns` | (대화 id, 순번 `u32`) | 말 JSON(`Turn`: 글, 한 일, 열린 시트) |

- 목록은 요약만 읽어 마지막 시각 순으로 정렬한다(메모리에서, 대화 수천 개까지 문제없음). 말은 대화를 열 때 읽는다.
- 쓰는 때: 답이 끝날 때(`Done`/`Failed`)와 멈출 때. 스트리밍 중에는 쓰지 않는다. 지난번에 쓴 뒤의 말만 쓰고,
  대화보다 뒤에 남은 옛 순번은 지운다. 쓰기는 백그라운드에서, 앞의 쓰기가 끝난 뒤에 한다(늦게 끝난 옛 쓰기가 새
  말을 지우지 않게). 실패하면 알리고 다음에 대화 전체를 다시 쓴다.
- 승인 카드: 쓰는 때에는 기다리는 카드가 이미 거절(`Declined`)로 바뀌어 있다. 다시 연 대화의 카드는 읽기 전용이다.
- 시트: 사용자 말(`Turn::sheet`)에 그때 열린 시트의 라이브러리 기준 경로를 적는다. 모델에 보낼 때 직전 사용자 말과
  시트가 다르면 말 앞에 `[The user switched to the sheet …]`(닫았으면 `[The user closed the sheet …]`)를 붙인다.
  앞의 말이 다른 시트를 두고 한 것임을 모델이 알게 한다. 요약의 시트 목록은 "이 시트" 거르기에 쓴다.
- 다시 연 대화는 그대로 이어 간다. 프롬프트의 시트는 지금 열린 시트다. 허락한 사이트도 되살린다.
- 기록 화면: 오늘·어제·지난 7일·이전으로 묶는다(지역 날짜, `chrono`). 줄 위에 올리면 지우기 버튼이 보인다.

## 결과 (Consequences)

- (+): 원고 전체를 다루는 대화와 시트 하나를 다듬는 대화가 한 목록에 있고, 필요하면 시트로 거른다.
- (+): 시트를 옮기거나 지워도 대화가 남는다.
- (+): 답 하나에 바뀐 말만 써서 대화가 길어져도 쓰기 비용이 늘지 않는다.
- (-): 키가 라이브러리 경로 해시라 라이브러리 폴더를 옮기면 기록이 이어지지 않는다. 필요해지면 라이브러리 ID를
  `.writer.toml`에 둔다.
- (-): 옮긴 시트의 옛 대화는 "이 시트"로 거를 때 보이지 않는다(옛 경로로 적혀 있다).
- (-): 다른 기기와 기록을 나누지 않는다.

## 대안 (Alternatives)

- 시트별 대화 기록: 한 시트에 속하지 않는 대화를 둘 곳이 없고, 시트 이동·삭제를 따라가야 한다.
- `cache.redb`에 테이블 추가: 캐시는 지워도 되는 데이터만 두므로 다시 만들 때 기록이 사라진다.
- 라이브러리 안 `.writer/conversations/`(대화마다 JSON 파일): 라이브러리와 함께 옮겨지지만 동기화·Git에 대화가
  섞이고, 대화가 많아지면 목록을 읽을 때 파일을 모두 열어야 한다.
