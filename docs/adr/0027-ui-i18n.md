# ADR-0027: UI 글은 rust-i18n으로 영어·한국어를 고른다

- 상태: Proposed
- 날짜: 2026-10-23
- 관련: `src/i18n.rs`, `locales/<언어>/*.yml`, `src/settings.rs`(언어 선택), `src/menus.rs`

## 배경 (Context)

화면 글이 모두 한국어로 코드에 박혀 있다. 영어 사용자도 쓸 수 있어야 하고, 지원 언어는 영어와 한국어 둘이다.

## 결정 (Decision)

- **rust-i18n 4**를 쓴다. gpui-component가 이미 쓰는 크레이트라 로캘(`rust_i18n::set_locale`)을 함께 쓴다.
  번역은 컴파일할 때 바이너리에 들어간다.
- 파일: 언어마다 폴더를 두고 영역마다 파일을 나눈다: `locales/<언어>/<영역>.<언어>.yml`(`_version: 1`).
  rust-i18n은 파일 이름의 마지막 `.` 뒤를 로캘로 읽으므로 이름에도 언어를 붙인다. 언어를 더하려면 폴더 하나를
  더한다. 키 앞머리는 영역 이름이다(`menu.`, `settings.`, `library.` …). 여러 화면이 쓰는 짧은 글은 `common`.
  - 키는 `<영역>.<자리>.<이름>` 소문자·밑줄. 값은 늘 큰따옴표로 감싼다(YAML이 `Off`·`yes`를 불리언으로 읽는다).
  - 끼워 넣는 값은 `%{name}`, 코드에서 `t!("key", name = value)`.
  - `ko` 값은 원래 코드의 한국어 그대로다. 한국어 화면은 바뀌지 않는다.
  - 테스트가 `en`·`ko` 키 목록이 같은지 본다.
- 언어 설정: 설정 → 일반 → 언어(시스템 설정 / English / 한국어). `config.toml`의 `language`(`en`·`ko`, 없으면 시스템).
  시스템 언어가 한국어가 아니면 영어. 바꾸면 메뉴를 다시 설치하고 창을 다시 그린다. 이미 만들어 둔 입력 칸의
  placeholder 같은 상태는 그 화면을 다시 열 때 바뀐다.
- 번역하지 않는 것:
  - 모델이 읽는 글(도구 설명, 시스템 프롬프트, 도구 결과·오류). 이미 영어이고 답은 사용자 언어로 한다.
  - 책 내용(내보내기의 목차·표지 대체 글, 기본 장 머리말 같은 스타일 값). 책의 `language`를 따를 일이다.
  - 개발자용 기록(`eprintln!`), 테스트, 주석, 한국어 조판 규칙과 그 데이터, 디스크에 만드는 폴더·파일 이름.
  - 확장 앞머리의 설명(사용자가 쓴 언어 그대로, ADR-0026).

## 결과 (Consequences)

- (+): 번역하는 사람은 자기 언어 폴더만 본다. 빠진 키는 테스트가 잡는다(두 언어의 키 목록이 같아야 한다).
- (+): 메뉴도 언어를 따른다(전에는 영어로만 있었다).
- (-): `t!`는 없는 키를 키 이름 그대로 보인다(컴파일 때 잡지 않는다). 테스트는 두 언어의 키가 맞는지만 본다.
- (-): 열려 있는 대화상자 일부는 다시 열어야 새 언어로 보인다.
- 후속(TODO): 책 내용 글을 책의 `language`로 고르기, 빌트인 스킬의 언어별 본문.

## 대안 (Alternatives)

| 대안 | 기각 사유 |
| --- | --- |
| Fluent(`fluent-rs`) | 복수형·성 변화는 낫지만 두 언어에는 과하고, gpui-component와 로캘을 따로 맞춰야 한다 |
| 직접 만든 `match` 표 | 키가 늘수록 언어별로 흩어지고 빠진 번역을 찾기 어렵다 |
| 키 하나에 두 언어를 함께 적기(`_version: 2`) | 처음엔 이렇게 했다. 두 언어에선 편하지만 언어를 더할수록 파일마다 손대야 하고, 번역을 따로 맡기기 어렵다 |
