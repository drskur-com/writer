# ADR-0046: 확장 그림은 렌더 스레드들이 그리고, UI는 지난 이미지를 보이다가 다음 프레임에 바꾼다

- 상태: Proposed
- 날짜: 2026-10-23
- 관련: ADR-0042(vello_cpu로 그리기), ADR-0045(3차원 깊이 버퍼) · `src/app/extension_painter.rs`

## 배경 (Context)

ADR-0042·0045 뒤로 그림 한 장(래스터·BGRA 변환·이미지)이 UI 스레드에서 1~6ms, 3차원 장면은 10ms 안팎이 들었다. 애니메이션 블록이
보이면 그 시간만큼 매 프레임 스크롤·입력이 무거워진다.

## 결정 (Decision)

**`paint`는 그리지 않고 렌더 스레드(코어 수 − 1, 4개까지)에 맡긴다. 캔버스마다 한 번에 하나만 맡기고, 결과가 오면 다음 프레임에 바꾸며,
그동안은 지난 이미지를 보인다.**

- 맡길 때 모양 목록을 복사해 넘긴다(그림은 `Arc`라 복사하지 않는다). 스레드마다 렌더 문맥을 하나 들고 다시 쓴다.
- 결과를 기다리는 동안은 `request_animation_frame`으로 다음 프레임에 다시 와서 받았는지 본다.
- 맡긴 일이 끝났을 때 모양이 또 바뀌었으면 그때의 최신 모양을 맡긴다. 그래서 렌더가 프레임보다 느리면 중간 프레임을 건너뛴다.

## 결과 (Consequences)

- (+): UI 스레드는 열쇠 계산과 모양 복사만 한다. 그리기가 느린 블록도 편집을 막지 않는다. 블록 여럿이 여러 스레드에서 함께 그려진다.
- (-): 처음 보일 때와 크기가 바뀔 때 한두 프레임은 비어 있거나 늘린 옛 그림이다. 애니메이션은 한 프레임쯤 늦다.
- (-): 기다리는 동안 창을 프레임마다 다시 그린다(수 ms).

## 대안 (Alternatives)

| 대안 | 기각 사유 |
| --- | --- |
| 확장 작업 스레드가 `draw` 다음에 바로 그린다 | 책 미리보기·대화상자처럼 작업 스레드 없이 모양만 있는 곳이 있고, 픽셀 크기는 그릴 때 정해진다 |
| 새 모양이 오면 맡긴 일을 버린다 | 렌더가 프레임보다 느리면 아무것도 보이지 않는다 |
