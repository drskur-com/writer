# ADR-0019: 시트를 끌어 다른 그룹으로 옮기면 파일을 옮기고 두 그룹의 순서·접합을 함께 저장한다

- 상태: Proposed
- 날짜: 2026-10-22
- 관련: ADR-0012, ADR-0014 · `src/library/meta.rs`, `src/app/sheet_list.rs`, `src/app/library_panel.rs`, `src/app/project_panel.rs`, `src/app/library_ops.rs`

## 배경 (Context)

ADR-0014는 한 그룹 안에서 시트를 개별로 옮기는 규칙만 정했다. 그래서 시트를 다른 그룹으로 보내려면
파일을 Finder에서 직접 옮기거나 그룹을 다시 만들어야 했다. 사이드바의 그룹 줄은 시트를 받지 못했고,
시트 목록의 끌기는 수동 정렬 그룹에서 순서를 바꾸는 데만 쓰였다.

그룹은 실제 폴더이고 시트는 그 폴더 안의 마크다운 파일이다. 그룹 사이 이동은 곧 파일 이동이며,
원본·대상 그룹의 `.writer.toml`에 있는 `sheets`·`glued`도 함께 맞춰야 한다.

## 결정 (Decision)

**시트 카드 하나 또는 선택한 시트들을 끌어 다른 그룹 줄(또는 프로젝트 제목·프로젝트 그룹 줄)에 놓으면,
그 시트들의 파일을 대상 그룹 폴더 끝으로 옮기고 양쪽 그룹의 순서·접합을 저장한다.**

- 끌기는 시트 그룹이면 정렬 방법과 관계없이 된다. 목록 안 순서 바꾸기는 지금처럼 수동 정렬일 때만 한다.
- 여러 시트를 고른 채 그중 하나를 끌면 선택한 시트를 목록 순서대로 함께 옮긴다. 미리보기는 첫 이름과
  “외 N개”를 보여 준다.
- 대상 그룹은 시트 그룹만 된다. 파일 그룹(첨부파일 등)과 원본과 같은 그룹에는 놓을 수 없다.
- 대상 그룹에 같은 파일명이 있으면 `이름 2.md`처럼 비어 있는 이름으로 옮긴다.
- 원본에 남은 시트의 접합은 유지한다(묶음 가운데를 빼도 앞뒤가 이어진다). 옮긴 묶음 안에서 원래
  이어져 있던 시트의 접합도 유지하되, 대상 그룹의 마지막 시트와는 접합하지 않는다.
- 열린 시트를 옮기면 먼저 저장하고 새 경로로 편집을 이어 간다. 프로젝트가 바뀌면 새 프로젝트의
  책 스타일을 다시 입힌다. 선택 상태의 시트 경로도 새 경로로 바꾼다.
- 옮겨서 `../` 깊이가 어긋난 이미지 경로는 원문을 고치지 않고 ADR-0021 규칙으로 계속 찾는다.
- 파일 이동이나 메타 저장이 실패하면 옮긴 파일과 대상 메타를 되돌리고, 메모리의 두 그룹 모델은
  성공했을 때만 바꾼다.
- “모두”(섹션) 목록은 여러 그룹의 시트가 섞여 있어 끌기 출발점으로 쓰지 않는다.

## 결과 (Consequences)

- (+): 그룹을 옮길 때 Finder를 열 필요 없이 사이드바에서 시트를 보낼 수 있다.
- (+): 정렬 방법을 수동으로 바꾸지 않아도 그룹 사이 이동을 할 수 있다.
- (+): 접합과 열린 편집 상태가 이동 뒤에도 이어진다. 저장 실패 시 파일이 원래 자리로 돌아간다.
- (-): 그룹 줄에 놓으면 항상 대상 목록 끝에 붙는다. 대상 목록의 특정 카드 사이에 끼워 넣는 동작은 없다.
- (-): 이동은 UI 스레드에서 파일 이름 바꾸기와 메타 쓰기를 한다. 아주 많은 시트를 한 번에 옮기면 잠깐 멈출 수 있다.
- 후속(TODO): “모두”에서 여러 그룹의 시트를 골라 한 번에 옮기기, 대상 목록의 특정 위치에 끼워 넣기.

## 대안 (Alternatives)

| 대안 | 기각 사유 |
| --- | --- |
| 목록 위치(index)만 끌기 정보로 넘긴다 | 정렬된 목록의 위치와 그룹 메타의 실제 순서가 달라 다른 시트를 옮길 수 있다 |
| 파일을 복사한 뒤 원본을 지운다 | 실패했을 때 되돌리기 어렵고 큰 파일에서 느리다 |
| 파일은 두고 메타에 소속 그룹만 적는다 | 그룹 폴더가 소속을 정하는 기존 구조와 Finder·동기화가 어긋난다 |
| 항상 접합을 해제하고 옮긴다 | 같은 묶음 일부만 옮길 때 다시 접합해야 한다 |
| “모두”에서도 그대로 끈다 | 선택이 여러 원본 그룹에 걸칠 수 있어 그룹별 이동을 따로 설계해야 한다 |
