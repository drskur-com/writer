# ADR-0049: 움직이는 GIF는 원본을 압축된 채 들고 필요한 프레임만 푼다(에디터 재생, 확장의 `img:frameAt(t)`)

- 상태: Proposed
- 날짜: 2026-10-24
- 관련: ADR-0008(에디터 이미지 줄), ADR-0046(렌더 스레드) · `src/gif.rs`, `src/app/gif_player.rs`, `src/app/editor_image.rs`, `src/extension/image.rs`, `src/extension/canvas.rs`

## 배경 (Context)

에디터의 로컬 이미지는 QuickLook 썸네일(프레임 하나)이라 GIF가 움직이지 않았다. gpui `img`는 GIF를 움직이지만 처음에 모든 프레임을
RGBA로 펼쳐 둔다. 500×500, 100프레임이면 원본 1~2MB가 약 100MB가 된다. 브라우저는 원본을 들고 필요한 프레임만 푼다. 프레임 수와
프레임마다의 표시 시간은 GIF마다 다르고, 프레임 수는 헤더에 없다.

## 결정 (Decision)

**프레임이 여럿인 로컬 GIF(64MB까지)는 재생기가 원본을 들고, GIF마다 디코딩 스레드 하나가 다음 프레임 하나만 미리 풀어 표시 크기로
줄여 둔다. 프레임은 그려질 때만 넘긴다.**

- 훑기(`gif::scan`): 그림 데이터는 풀지 않고 블록 길이만 따라 프레임 수와 반복 횟수를 구한다. 한 장짜리·너무 큰 GIF는 썸네일로 보인다.
- 반복: NETSCAPE2.0 블록(0 = 무한, n = n번 더). 없으면 한 번만 재생하고 마지막 프레임에 멈춘다.
- 시간: 프레임마다 적힌 지연을 따른다. 10ms 이하는 100ms로 고친다(브라우저와 같다). 다음 차례에 창을 다시 그리는 타이머를 건다.
- 멈춤: 화면 밖·비활성 창은 그리지 않으므로 멈춘다. 움직임 줄이기 설정이면 첫 프레임만 보인다. 5초 그리지 않으면 스레드와 프레임을
  버리고, 다시 보이면 처음부터 푼다.
- 크기: 썸네일과 같이 본문 최대 폭 기준 크기(화면 배율 포함)로 줄여 푼다. 창 폭이 바뀌어도 다시 풀지 않는다.
- 웹 주소 GIF는 그대로 gpui `img`(모두 펼침)로 보인다.

**확장은 `g.newImage`의 GIF에서 `img:frameAt(t)`·`img:frame(n)`으로 프레임을 받아 `g.draw`로 그린다.**

- `frameAt(t)`: 훑을 때 모은 프레임별 시간과 반복으로 번호를 구한다(풀지 않는다). 반복을 다 돌면 마지막 프레임이다.
  `getFrameCount()`·`getDuration()`도 둔다. 움직이지 않는 그림은 1프레임·0초이고 자기 자신을 돌려준다.
- 풀기: 프레임 반복자는 스레드를 넘지 못해 Lua 작업 스레드마다 그림별 디코더를 둔다. 앞으로 가면 이어서 풀고(차례로
  재생하면 프레임마다 하나), 뒤로 가면 처음부터 푼다. 그림마다 최근 4프레임을 남긴다. 푸는 시간은 호출 시간 제한에서 뺀다.
- `g.draw(img)`는 그대로 첫 프레임이다. 내보내기는 고른 프레임을 PNG로 넣는다(원본 GIF를 넣으면 ePub에서 움직인다).

## 결과 (Consequences)

- (+): 메모리는 원본 + 프레임 두 장(표시 크기) + 디코더의 합성 버퍼다. 프레임 수와 상관없다.
- (-): 프레임마다 디코딩과 텍스처 교체를 한다. 같은 GIF가 여러 번 나오면 각자 푼다(시트 안에서는 경로마다 하나).
- (-): 앞에서부터만 풀 수 있어 뒤로 가거나 건너뛰면 처음부터 푼다. 프레임이 아주 많은 GIF를 거꾸로 돌리면 느리다.

## 대안 (Alternatives)

- gpui `img`에 파일 경로를 넘긴다: 가장 간단하지만 모든 프레임을 펼친다.
- 프레임 수·크기 상한을 두고 펼친다: 큰 GIF는 움직이지 않게 된다.
