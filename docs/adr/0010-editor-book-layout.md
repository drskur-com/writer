# ADR-0010: 에디터는 책 스타일대로 문단을 배치하고, 블록 사이 여백은 앞 줄 아래에 둔다

- 상태: Proposed
- 날짜: 2026-10-20
- 관련: ADR-0006, ADR-0008, ADR-0009, ADR-0011 · `vendor/gpui-base`, `docs/patches/gpui-base-0.8.0-line-layout.patch`, `docs/patches/gpui-base-0.8.0-line-block-style.patch`, `src/app/editor_layout.rs`, `src/app/editor.rs`

## 배경 (Context)

ADR-0009의 책 스타일(정렬·첫 줄 들여쓰기·문단 간격·제목 앞뒤 여백)을 에디터에도 보여야 한다.
지금 에디터는 마크다운 원문을 줄 단위로 그리고, 줄별로 바꿀 수 있는 것은 글자 크기·행 높이·접기·아래 블록뿐이다(ADR-0006, ADR-0008).

- 마크다운 기호는 지금처럼 흐리게 두고, 문단 모양만 책 기준으로 맞춘다.
- 블록 사이 여백은 다음 줄을 알아야 정할 수 있다. 예를 들어 문단 뒤에 제목이 오면 둘의 여백 중 큰 값을 둔다. 그런데 줄 스타일 함수는 줄 텍스트 하나만 받는다.
- 양쪽 정렬은 행마다 단어(또는 글자) 사이를 벌려야 하고, 커서·선택·클릭도 벌어진 위치를 따라야 한다.

## 결정 (Decision)

**gpui-base 패치를 넓혀 줄 단위 가로 배치와 줄 아래 여백을 더하고, 줄 스타일 함수가 앞뒤 줄을 보게 한다.
앱은 마크다운 블록 규칙으로 책 스타일을 줄 스타일로 옮긴다.**

엔진(`LineStyle`, gpui-base 패치):
- `first_indent`: 첫 행의 왼쪽 오프셋. 첫 행은 그만큼 좁게 줄바꿈한다.
- `align`(`Start`·`Center`·`End`·`Justify`): 줄바꿈 폭 안에서 행을 놓는 방식. 행 끝 공백은 폭에서 뺀다.
  - 양쪽 정렬은 마지막 행을 뺀 행을 줄바꿈 폭까지 늘린다. 공백 묶음마다 같은 몫을 더하고, 공백이 없는 행(CJK)은 글자 사이에 나눈다.
  - 단어는 따로 shape해 벌린 위치에 그리고, 공백 묶음은 그리지 않는 간격 조각이 된다. 기존 인라인 조각(`InputLine::inline`)을 그대로 쓰므로 커서·선택·클릭 판정이 벌어진 행을 따른다.
- `space_after`: 줄 아래(블록 아래) 빈 공간. 높이 계산은 기존 블록과 같은 경로를 쓰고, 블록 렌더러에는 넘기지 않는다.
- 줄 스타일 함수는 `LineContext { text, prev, next }`를 받는다. 줄이 바뀌면 바로 앞뒤 줄도 다시 스타일한다.

앱 규칙(`editor_layout.rs`, 길이 단위 em = 본문 글자 크기). 에디터에서는 줄 하나가 문단이다(ADR-0011):
- 문단 줄은 본문 정렬과 첫 줄 들여쓰기를 쓴다.
- `#`·`##`·`###` 제목은 부·장·절 스타일의 크기·정렬·들여쓰기를 쓴다. 행 높이 = 크기 × 제목 줄 간격 / 본문 줄 간격.
- 줄 아래에 다음 블록과의 여백을 둔다. 두 블록 사이 여백 = max(앞 블록 뒤 여백, 뒤 블록 앞 여백)(CSS 여백 겹침과 같음).
  다음 줄이 빈 줄이면 문단 뒤 여백을 두고, 빈 줄은 그 아래 평범한 빈 행으로 남는다(접지 않음, 커서가 갈 수 있음).
- 목록·인용·코드 펜스·표·4칸 들여쓴 줄에는 들여쓰기와 정렬을 입히지 않고, 이런 줄끼리는 여백 없이 붙인다.
- 페이지 나눔 표시("여기서 페이지가 나뉩니다", epubly 편집 화면과 같음): 새 페이지에서 시작하는 제목(별도 제목 페이지·`page_break`, 숨긴 제목 포함)의 앞 줄 아래와 별도 제목 페이지인 제목 줄 아래.
  - 엔진(`line-block-style` 패치): 줄 스타일의 `block_height`에 측정한 블록 높이를 더한다. 줄 스타일이 앞뒤 줄을 보고 측정 블록(이미지) 밑에 몫을 잡는다.
    `LineStyle::block_before`는 첫 줄 것만 써서 문서 위 머리 블록이 된다(내용과 함께 스크롤). 세로 위치는 모두 `DisplayMap::display_row_top`을 거치므로 그리기·클릭·스크롤이 함께 내려간다. 블록 렌더러는 `LineBlockContext::above`로 구분한다.
  - 앱: 블록 렌더러는 측정 몫(이미지)을 그리고 남은 몫에 표시를 그린다. 나뉜 뒤에는 다음 제목의 앞 여백을 두지 않는다(새 페이지 첫머리).
  - 시트 첫 줄이 새 페이지 제목이면(시트마다 장 하나) 첫 줄 위 블록에 표시한다.
- 툴바 ¶ 버튼은 커서 줄을 본문·부·장·절 제목(`#`~`###`)으로 바꾼다(메모에서는 제목 1~3). 메뉴는 커서 줄의 지금 종류에 체크한다.

## 결과 (Consequences)

- (+): 에디터 화면이 내보낸 책과 같은 문단 모양이 된다. 양쪽 정렬된 행에서도 클릭한 곳에 커서가 놓인다(실제 마우스 클릭으로 확인).
- (+): 기존 gpui-base input 테스트 368개가 그대로 통과하고, 새 테스트 5개를 더했다(첫 줄 들여쓰기, 가운데·오른쪽 정렬, 양쪽 정렬 폭과 클릭 판정, 줄 아래 여백, 이웃 줄 다시 스타일).
- (+): 빈 줄을 접지 않아 커서 이동에 따라 레이아웃이 움직이지 않는다.
- (-): 패치가 커졌다(7파일 +515/−65). gpui-base를 올릴 때 다시 적용해야 한다(`docs/patches/gpui-base-0.8.0-line-layout.patch`, 앞의 두 패치 위에 적용).
- (-): 줄 판정이 앞뒤 한 줄만 보므로, 코드 펜스 안의 줄도 문단으로 볼 수 있다(펜스 시작 줄만 제외된다). 제목 오판정(ADR-0006)과 같은 문제다. 저장 변환(ADR-0011)은 펜스를 따라가므로 원문은 안전하다.
- (-): 양쪽 정렬 행의 공백에는 배경색(인라인 코드 등)을 그리지 않는다.

## 대안 (Alternatives)

| 대안 | 기각 사유 |
| --- | --- |
| 줄 스타일 함수는 그대로 두고 앱이 문서 전체를 보고 줄별 스타일 목록을 넘김 | 편집할 때마다 목록을 다시 만들고 줄 번호 이동을 맞춰야 한다. 엔진이 고친 줄만 다시 판정하는 구조와 맞지 않는다 |
| 마크다운 원문 그대로 편집하고 문단 사이 빈 줄을 접어 여백으로 표시(커서가 들어오면 펼침) | 커서 이동마다 레이아웃이 움직이고 빈 줄 클릭 판정이 복잡하다. 줄 = 문단(ADR-0011)이면 문단 사이에 빈 줄이 없다 |
| 제목 앞 여백을 행 위쪽 여백으로 따로 둠 | 높이 계산·커서·클릭 경로를 하나 더 고쳐야 한다. 앞 줄 아래 여백(max 규칙)으로 충분하다 |
| 양쪽 정렬을 글리프 간격(letter-spacing)으로 | gpui `TextRun`에 자간이 없다 |
| 에디터는 왼쪽 정렬만, 미리보기에서만 책 모양 | 쓰는 화면과 책 모양이 달라 문단 호흡을 보며 쓸 수 없다 |
