# ADR-0055: 받아쓰기 기록에는 원문만 쓰고, LLM은 1분마다 고른 언어로 요약만 고쳐 쓴다

- 상태: Proposed
- 날짜: 2026-10-25
- 관련: ADR-0054(받아쓰기 모델·기록), ADR-0053(OCR의 LLM 옵션, 같은 원칙), ADR-0048(Token Plan), ADR-0011(줄 하나가 문단) · `src/agent/dictation.rs`(요약 프롬프트·요청), `src/dictation/output.rs`(쓰기 스레드), `src/dictation/recognizer.rs`(인식 작업 스레드), `src/app/dictation.rs`(녹음 막대), `src/app/dictation/ai.rs`(요약), `src/settings.rs`(받아쓰기 페이지), `src/config.rs`(`[dictation]`)

## 배경 (Context)

강의·회의를 받아 적으며, 길어지면 지금까지의 요점을 내가 읽는 언어로 보고 싶다. 받아 적은 글은 군말·잘못 알아들은 단어가 섞인다.

- 받아쓰기(ADR-0054)는 기기 안에서 하고 음성은 밖으로 보내지 않는다. LLM은 설정의 AI 제공자(Bedrock·Token Plan)라 받아 적은 글이 밖으로 나간다.
- 녹음 중인 기록 파일은 인식 작업 스레드만 끝에 덧붙인다. 에디터는 읽기 전용이다(원자적 저장이 파일을 바꿔치우면 덧붙인 문단이 사라진다). 쓰는 쪽이 늘면 같은 문제가 생긴다.
- Nemotron은 언어를 알아서 읽지만 문단마다 새로 알아내므로, 짧은 문단이 엉뚱한 언어·글자(한국어 말이 중국어·힌디어·러시아어 글자로)로 적히곤 한다.
- 처음에는 몇 문단씩 모아 LLM이 번역(외국어)하거나 다듬은(사용 언어) 글을 그 묶음 아래 `> …`로 끼워 넣었다. 써 보니 원문과 `>` 줄이 번갈아 나와 읽기 어렵고, 엉뚱한 언어로 적힌 조각을 LLM이 그럴듯한 말로 지어내 옮겼다(`Să sorecta.` → "고치도록 하시오.").
- OCR의 "AI로 읽기"(`agent/transcribe.rs`)가 대화 맥락·도구 없이 지시와 입력만 보내는 한 번의 요청이다.

## 결정 (Decision)

**기록에는 받아 적은 원문만 쓴다. 녹음 중 번역·다듬기는 하지 않는다.** 원문은 문단이 맺히면 바로 기록 끝에 덧붙인다.

**파일 하나에는 쓰는 쪽이 하나다.** 녹음 중 기록에는 쓰기 스레드만, 요약 파일에는 요약 작업만, 녹음 뒤에는 에디터만 쓴다. 인식 작업 스레드는 쓰기 스레드가 남은 문단을 다 쓸 때까지 기다린 뒤 끝을 알린다.

| 하는 일 | 언제 | 쓰는 곳 | 쓰는 쪽 |
| --- | --- | --- | --- |
| 받아쓰기 원문 | 문단마다 | 기록 끝 | 쓰기 스레드(인식 작업 스레드가 맺은 문단을 채널로 넘긴다) |
| 요약 | 1분마다 | 요약 파일 | 요약 작업 |
| 요약 넣기 | 녹음 뒤 | 기록 | 앱(요약 파일을 읽어 기록에 넣는다) |

**설정 → 받아쓰기에 LLM 옵션을 둔다. 기본은 끔이다.**

- 녹음 중 요약(켬·끔), 요약 언어(기록의 언어 그대로 / 16개 언어. 예전 `translate_to` 설정을 그대로 잇는다), 쓸 모델(제공자의 모델 중에서, 제공자별로 저장. 고르지 않으면 어시스턴트의 모델). AI 제공자를 설정하지 않았으면 설정 → AI를 안내한다.
- 켜면 받아 적은 글이 어느 제공자로 가는지 보인다. 음성은 여전히 보내지 않는다.

**요약: 1분마다(`config::SUMMARY_MINUTES`) 기록과 짝인 요약 파일을 고른 언어로 고쳐 쓴다.**

- 요약 파일은 `STT/.summaries/<기록 ULID>.md`다. 점으로 시작하는 폴더라 라이브러리 목록에 시트로 보이지 않는다.
- 직전 요약과 그 뒤로 새로 쌓인 문단만 보내 요약을 고친다. 녹음이 길어도 요청 크기가 일정하다. 새 문단이 있을 때만 보내므로 1시간에 많아야 60번쯤이다. 앞 요약이 아직 돌면 기다린다.
- 프롬프트는 받아쓰기가 일부를 엉뚱한 언어·글자로 적을 수 있다고 알리고, 맥락에 맞지 않는 조각은 건너뛰게 한다. 요약은 고른 언어(없으면 기록의 언어)로 쓴다.
- 요약은 저절로 고쳐지고, 녹음 막대의 "요약 보기"로 막대 위쪽에 따로 된 패널로 펼쳐 본다(머리줄에 요약 주기와 닫기가 있고, 본문은 높이가 정해져 패널 안에서 스크롤한다). 녹음 중에는 요약이 고쳐질 때마다 바로 바뀌고, 녹음이 끝난 뒤에는 고른 기록의 요약 파일을 보인다. 넣거나 버리면 접는다.
- 녹음이 끝나면 남은 원문으로 마지막 요약을 한다. 그 기록을 보고 있으면 녹음 막대에 "이 기록의 요약이 있습니다 · 요약 보기 · 버리기 · 맨 아래에 넣기"를 보인다. 넣으면 기록 맨 끝에 `## 요약`과 주제 제목·글머리표 줄로 넣고 요약 파일을 지운다. 이미 요약 구간이 있으면 지우고 새 끝에 넣는다.
- 요약은 주제별로 제목 줄(`### 주제`)과 그 아래 글머리표 줄(`- `)로 쓰게 한다(다른 수준의 제목은 `### `로 맞추고 빈 줄은 뺀다). 패널은 주제 제목을 굵게 보이고, 기록에 넣으면 `## 요약` 아래에 그대로 들어간다. 이어서 녹음할 때는 요약 파일(없으면 기록의 요약 구간)에서 이어 고친다.

**녹음 뒤 다듬기·번역은 두지 않는다.** 기록은 보통 시트라 오른쪽 AI 어시스턴트에게 맡긴다.

## 결과 (Consequences)

- 좋아지는 점(+): 기록이 받아 적은 그대로라 읽기 쉽고, LLM이 지어낸 말이 기록에 섞이지 않는다. 다른 언어 강의도 요약은 내 언어로 1분 간격으로 본다. 쓰는 쪽이 파일마다 하나라 기록이 깨지지 않는다.
- 감수하는 점(-): 원문 자체는 다른 언어로 읽을 수 없다(요약만 옮겨진다). 켜면 받아 적은 글이 외부 제공자로 나가고, 녹음 시간에 비례해 비용이 든다. 잘못 알아들은 단어는 기록에 그대로 남는다.
- 후속 작업(TODO): 받아쓰기 인식 언어를 고르게 하기(Nemotron은 언어 힌트(`RunOptions.language`, `ko`·`en` 등)를 받는다). 요약 주기를 써 보며 맞추기. 기록을 지우거나 옮길 때 요약 파일도 함께 옮기기.

## 대안 (Alternatives)

| 대안 | 기각 사유 |
| --- | --- |
| 몇 문단씩 모아 번역·다듬은 글을 묶음 아래 `> …`로 끼워 넣기 | 만들어 써 보았다. 원문과 `>` 줄이 번갈아 나와 읽기 어렵고, 엉뚱한 언어로 적힌 조각을 그럴듯하게 지어내 옮겼다 |
| 문단이 맺힐 때마다 번역 요청 | 짧은 문단마다 요청이 나가 비용·요청 수가 크고, 맥락이 짧아 번역이 어색하다 |
| 요약 주기 5분 | 녹음 중 요점을 보기에 너무 늦다 |
| 요약을 기록 맨 위에서 고쳐 쓰기 | 작업 스레드가 덧붙이는 파일을 다른 쪽이 고치게 되어 문단을 잃는다 |
| 요약을 기록 끝에 덧붙이기 | 받아 적은 글 사이에 요약이 끼어 읽기 어렵다 |
| 요약할 때마다 기록 전체를 보내기 | 녹음이 길어질수록 요청이 한없이 커진다 |
| 녹음 뒤 "AI로 다듬기" 버튼(묶음으로 나눠 다듬고 diff로 확인) | 만들어 보았으나 AI 어시스턴트로 시트를 다듬는 것과 겹쳐 뺐다 |
| LLM으로 화자 나누기 | 글만으로 짐작해 여러 사람이면 자주 틀리고, 쉼으로 나눈 문단 안의 말 바뀜을 못 맞춘다 |
