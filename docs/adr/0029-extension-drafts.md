# ADR-0029: 어시스턴트가 고친 확장은 답 동안 초안에 두고, 답이 끝나면 확장마다 한 번 승인받는다

- 상태: Proposed
- 날짜: 2026-10-23
- 관련: ADR-0026(확장), `src/agent/tools.rs`(`drafts`, `save_draft`, `take_drafts`), `src/agent/bedrock.rs`(`approve_drafts`),
  `src/agent/mod.rs`(`request_turns`), `src/agent/prompt.rs`, `resources/skills/extension/SKILL.md`

## 배경 (Context)

`run_extension`이 그림을 보여 주면서(ADR-0026) 모델이 "고치기 → 그려 보기 → 다시 고치기"를 여러 번 돌 수 있게 됐다.
그런데 파일 변경은 하나하나 승인 카드를 띄우므로, 고칠 때마다 사용자를 기다리고 사용자는 같은 파일의 diff를 여러 번
본다. 모델도 승인을 아끼려고 일찍 멈춘다. 도구 라운드 상한(24)도 이 반복에는 짧다.

## 결정 (Decision)

- `Extensions/<이름>.lua`에 대한 `write_file`·`edit_file`은 승인 없이 **초안**(메모리, 요청마다 새로)에 담는다. 디스크와
  시트의 블록은 그대로다. 처음 내용은 첫 변경 때의 것을 지키고, 초안이 원래 내용으로 돌아가면 초안을 지운다.
- `read_file`·`edit_file`·`run_extension`·`list_files`(아직 없는 새 확장)는 초안을 본다.
- 답이 끝나면(정상 종료, 라운드 상한, 오류 모두) 확장마다 승인 카드 하나(처음 → 마지막 diff)를 띄운다. 쓰기는 기존
  `commit`으로, 그사이 파일이 바뀌었으면 쓰지 않는다. 사용자가 답을 멈추면 남은 초안은 버린다.
- 거절했거나 쓰지 못한 변경은 다음 요청에서 그 답 끝에 `[Not applied: …]`로 적어 보낸다(도구 결과는 다시 보내지 않으므로).
- 도구 라운드 상한을 24에서 60으로 올린다.
- 다른 파일(시트, 설정, 스킬)은 지금처럼 매번 승인받는다.

## 결과 (Consequences)

- (+): 확장 작업에서 승인은 확장마다 한 번이고, 모델은 그림을 보며 자유롭게 다듬는다.
- (+): 확장은 sandbox에서만 돌고(ADR-0026) 초안은 디스크에 닿지 않으므로, 승인 전까지 라이브러리는 바뀌지 않는다.
- (-): 승인 카드가 답 글 뒤에 온다. 답에서 "고쳤다"고 해도 거절하면 적용되지 않는다(다음 요청에 알린다).
- (-): 답 동안 사용자는 시트에서 초안을 볼 수 없다.
