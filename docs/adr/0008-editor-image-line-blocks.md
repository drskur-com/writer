# ADR-0008: 에디터 이미지는 이미지 줄 아래 "줄 블록"으로 그리고, 이미지 줄은 커서가 있을 때만 보인다

- 상태: Proposed
- 날짜: 2026-10-20
- 관련: PLAN.md 스파이크 B·R2, ADR-0006, ADR-0007, `vendor/gpui-base`, `docs/patches/gpui-base-0.8.0-line-block.patch`, `src/app/editor_image.rs`, `src/markdown/mod.rs`(`image_line`)

## 배경 (Context)

에디터에서 시트에 넣은 이미지를 바로 보고 싶다. 지금은 `![캡션](경로){속성}` 글자만 보인다.

- 시트는 일반 `.md`다. 이미지 줄도 사용자가 그대로 고칠 수 있는 글자여야 한다.
- gpui-base 0.8.0의 인라인 토큰(`InlineToken`)은 원문 범위를 원자적인 칩으로 바꾼다. 한 줄 높이 안에 그리고, 토큰 안은 고칠 수 없다.
- ADR-0006 패치로 줄마다 행 높이를 바꿀 수 있다. 하지만 배율이라 글자도 커지고, 줄바꿈된 모든 행이 같이 커진다.

## 결정 (Decision)

gpui-base 패치에 **줄 블록**을 더한다. 줄의 마지막 행 아래에 픽셀 높이의 빈 칸을 두고, 앱이 그 칸에 요소를 그린다.

- API: `EditorState::set_line_blocks(measure, render, cx)`.
  - `measure(line, wrap_width) -> Pixels`: 줄 텍스트와 줄바꿈 폭으로 블록 높이를 정한다(0이면 없음). `LineStyle`처럼 줄을 다시 줄바꿈할 때 호출된다. 결과는 `LineStyle::block_height`에 들어간다.
  - `render(LineBlockContext { line, text, size }, window, cx) -> AnyElement`: 화면에 보이는 블록만 그린다.
- 블록 높이는 `DisplayMap`의 키 큰 행 목록에 줄 마지막 행의 추가 높이(px)로 들어간다. 스크롤·클릭 판정·선택 영역이 모두 이를 따른다.
- 블록을 누르면 그 줄의 마지막 행으로 친다(캐럿이 이미지 줄로 간다). 캐럿을 화면에 맞출 때는 블록을 빼고 글자 행만 본다.
- `LineStyle::collapsed`: 선택(캐럿 포함)이 닿지 않은 줄은 글자를 그리지 않고 행 높이를 0으로 둔다. 블록만 남는다.
  - 매 레이아웃 전에 선택이 닿은 줄 범위와 문서 리비전을 지난번과 비교하고, 바뀌었을 때만 접힘이 달라진 줄을 다시 잰다(`sync_revealed_lines`). 커서가 움직일 때 문서 전체를 다시 줄바꿈하지 않는다.
  - 화살표로 이미지 줄에 들어가거나 블록을 누르면 펼쳐지고, 나가면 다시 접힌다.
- 앱은 **이미지만 있는 줄**(`markdown::image_line`, 줄 텍스트만 봄)을 접고, 그 아래에 이미지와 캡션(alt)을 그린다. 캡션은 Pandoc `implicit_figures`가 그림 캡션으로 쓰는 것과 같은 자리다.
  - 크기·정렬은 ADR-0007 속성을 따른다. 크기를 적지 않으면 원본 크기를 쓰고, 높이는 480px까지로 줄인다. 어느 경우든 본문 폭을 넘지 않는다.
  - 로컬 파일은 헤더(`imagesize`)로 비율을 알아내고, 썸네일(`thumbnail::source`)로 그린다. 썸네일 크기는 본문 최대 폭 기준이라 창 폭이 바뀌어도 새로 만들지 않는다.
  - 웹 주소는 비율을 몰라서 정해진 칸(240px)에 맞춰 그린다. 파일이 없으면 안내 한 줄을 보여 준다.
- 이미지 뒤 `{…}` 속성도 이미지와 함께 기호로 흐리게 표시한다(ADR-0007 후속 작업).

## 결과 (Consequences)

- 좋아지는 점(+):
  - 쓰는 화면에는 이미지와 캡션만 보인다. 이미지 줄은 그대로 글자라 커서를 올리면 캡션·경로·속성을 바로 고칠 수 있고, 고치면 즉시 다시 그린다.
  - 판정이 줄 텍스트만 봐서 키 입력과 같은 프레임에 반영된다.
  - 블록이 없는 문서는 비용이 없다(`styled_lines` 요약이 0이면 건너뜀).
  - 기존 input 테스트가 그대로 통과하고 새 테스트 3개를 더했다(368개).
- 감수하는 점(-):
  - gpui-base 패치가 늘었다(`docs/patches/…line-block.patch`, 8파일 +516/−38). gpui-base를 올릴 때 ADR-0006 패치 다음에 적용한다.
  - 커서가 이미지 줄에 들어가고 나올 때 아래 내용이 한 줄 높이만큼 밀렸다 돌아온다.
  - 선택이 닿았는지 확인할 때 스타일이 있는 문서는 줄 목록을 한 번 훑는다(커서 줄이 바뀌거나 글이 바뀐 프레임에만).
  - 줄 텍스트만 보므로 코드 블록 안의 이미지 줄에도 이미지를 그린다(ADR-0006과 같은 한계).
  - 문장 안의 이미지, 인용·목록 안의 이미지는 그리지 않는다.
  - 이미지 헤더는 시트를 열어 둔 동안 캐시한다. 같은 경로의 파일을 밖에서 바꾸면 시트를 다시 열어야 반영된다.
  - 웹 이미지는 앱에 HTTP 클라이언트가 없으면 대체 아이콘만 보인다.
- 후속 작업(TODO):
  - 코드 펜스 안 오판정을 해결한다(ADR-0006 TODO와 함께).
  - 이미지를 눌러 같은 대화상자로 고치기(ADR-0007 TODO).
  - 웹 이미지의 실제 비율을 알아낸 뒤 `refresh_line_blocks`로 다시 재기.

## 대안 (Alternatives)

| 대안 | 기각 사유 |
| --- | --- |
| 이미지 줄 글자를 늘 보이기 | 경로가 길면 쓰는 화면이 지저분하다. 고칠 때만 필요하다 |
| 인라인 토큰(`InlineTokenRenderer`)으로 이미지 줄을 칩으로 바꾸기 | 한 줄 높이 안에서만 그린다. 토큰 안의 경로·속성을 고칠 수 없다 |
| `LineStyle::height_scale`로 이미지 줄을 키우기 | 글자 행 높이 배율이라 글자가 행 가운데로 밀리고, 줄바꿈된 행마다 커진다. 픽셀 높이를 줄 수 없다 |
| 에디터 위에 이미지를 겹쳐 그리기(오버레이) | 아래 줄이 밀리지 않아 글자를 가린다. 스크롤·클릭 판정을 따로 맞춰야 한다 |
| 프리뷰 팬에서만 이미지 보기 | 쓰는 화면에서 이미지 위치를 알 수 없다 |
