# ADR-0054: 받아쓰기는 기기 안의 Nemotron 3.5 ASR(handy-computer GGUF)로 하고, 메인 창의 받아쓰기 그룹에서 녹음해 라이브러리의 STT 폴더에 기록한다

- 상태: Proposed
- 날짜: 2026-10-24
- 관련: ADR-0011(줄 하나가 문단), ADR-0053(OCR, 같은 원칙) · `src/dictation/`(`mod.rs` 모델 내려받기, `recognizer.rs`, `capture.rs`), `src/app/dictation.rs`(녹음 막대), `src/settings.rs`(받아쓰기 페이지), `src/watch.rs`, `resources/macos/Info.plist.ext`

## 배경 (Context)

말로 원고를 쓰고 싶다. 음성은 밖으로 보내지 않는다(클라우드 인식은 고려하지 않는다). 강의·회의처럼 켜 두고 오래 받아 적는 일이 많다.

- macOS `SFSpeechRecognizer` 온디바이스는 한국어 짧은 문장은 괜찮지만 긴 받아쓰기·고유명사에 약하다. 더 나은 `SpeechAnalyzer`(macOS 26+)는 Swift 전용이다(ADR-0053에서 Swift 빌드를 기각한 것과 같은 이유).
- Windows의 자유 받아쓰기(`Windows.Media.SpeechRecognition` dictation, Win+H)는 Microsoft 온라인 서비스를 쓴다. 오프라인은 정한 문법(명령어)만 인식한다.
- NVIDIA Nemotron 3.5 ASR Streaming 0.6B(2026-06)는 한국어를 지원하고(FLEURS CER Q8_0 8.89%), 문장 부호를 붙이며, 진짜 스트리밍이다. 라이선스 OpenMDW-1.1(상업 사용 가능). Parakeet·Canary는 한국어가 없다.
- handy-computer가 transcribe.cpp용 GGUF(`handy-computer/nemotron-3.5-asr-streaming-0.6b-gguf`)를 올려 두었고, Rust 바인딩 `transcribe-cpp`(ggml, macOS Metal)가 있다. 시험: 한국어 합성 음성 7.1초를 M 시리즈 Metal에서 0.13초에 받아 적었다. 언어를 주지 않아도(자동) 한국어를 읽고 언어 태그를 남기지 않는다. 언어를 줄 때는 `ko-KR` 꼴이다.
- CPU만으로도 빠르다(모델 카드: Ryzen 4750U CPU에서 실시간의 10배).
- Hugging Face 캐시(`HF_HUB_CACHE` → `$HF_HOME/hub` → `~/.cache/huggingface/hub`)는 `hf` CLI·Handy 등이 함께 쓴다. 이미 받아 둔 사용자가 있다.
- gpui-kit에 녹음 상태(`SpeechState`)·파형·`SpeechRecognizer`/`AudioInput` 트레이트가 있다. 다만 `speech` 기능의 `Microphone`은 cpal 0.15라 rodio 0.23(cpal 0.18)과 ALSA 링크가 겹쳐 함께 빌드할 수 없다.

## 결정 (Decision)

**모델은 Nemotron 3.5 ASR Streaming 0.6B Q8_0 하나로 하고, 설정 → 받아쓰기의 모델 카드에서 내려받는다.**

- 양자화는 고르게 하지 않는다(일반 사용자에게 어렵다). Q8_0은 정확도가 원본과 같고 716 MiB다.
- 공식 `hf-hub` 크레이트(1.x)로 Hugging Face 캐시에 받는다. 캐시의 어느 스냅샷에든 파일이 있으면(예전 커밋으로 받은 것 포함) "내려받음"으로 보이고 다시 받지 않는다.
- 내려받기는 앱 전역 상태가 맡아 설정 창을 닫아도 이어진다. 진행률과 취소를 보이고, 실패하면 이유를 보인다.
- `hf auth login` 토큰이 없으면 로그인하면 더 빨리 받는다고 알린다.
- 지우기는 두지 않았다. 캐시는 다른 앱과 함께 쓴다.

**받아쓰기는 메인 창 사이드바의 "받아쓰기" 줄(`<라이브러리>/STT/`)이다. 기록 하나가 `STT/<ULID>.md` 하나다.**

- `STT/`는 섹션(`Notes`·`Projects`)이 아니라 사이드바 맨 위의 줄 하나다(`Library::stt`, 폴더가 없어도 빈 그룹). 고르면 시트 목록에 기록이 녹음한 순서(최근 것이 위)로 보이고, 기록은 보통 시트처럼 에디터에서 열고 고친다. 다른 그룹으로 옮기는 것은 시트 끌기로 한다(ADR-0019). 파일 → 받아쓰기는 이 줄을 고른다.
- 녹음 상태는 메인 창이 들고 있어 다른 시트로 옮겨 가도 녹음이 이어진다(강의를 받아 적으며 다른 시트에 메모한다). 녹음 중에는 사이드바 줄에 빨간 점과 지난 시간을 보인다.
- 에디터 칸 아래 녹음 막대: 받아쓰기를 보고 있으면 소리 고르기·녹음 버튼(빨간 점. 기록을 골랐으면 그 끝에 잇고, 아니면 새 기록)을, 녹음 중이면 어디서든 일시 정지(멈춘 기록을 다시 녹음하면 이어진다)·파형·지난 시간·지금 말하는 글(흐리게)을 보인다. 시트 목록의 작성 버튼은 다른 그룹과 같이 받아쓰기 그룹에 빈 시트를 만든다.
- 새 기록은 녹음을 시작할 때 만들어(첫 줄 `# 받아쓰기 YYYY-MM-DD HH:MM`) 연다. 말없이 끝나면 지운다. 고른 기록에 녹음하면 끝에 잇는다. 문단마다 한 줄(ADR-0011)을 덧붙인다. 파일은 표준 마크다운이라 문단 사이에 빈 줄을 둔다(빈 줄 없이 이으면 다시 열 때 한 문단으로 합쳐진다).
- 인식은 녹음마다 작업 스레드 하나가 한다. 모델을 불러 스트림에 160 ms씩 소리를 넣고, 글이 2초 동안 바뀌지 않으면(말이 끊기면) 문단을 맺어 파일에 쓰고 새 스트림을 연다. 쉬지 않고 말해도 3분에서 맺는다. 문단마다 스트림을 새로 열어 오래 켜 두어도 글이 한없이 자라지 않는다.
- 녹음 중인 기록 파일은 작업 스레드만 쓴다. 에디터에서는 읽기 전용이고 저장하지 않으며(원자적 저장이 파일을 바꿔치우면 작업 스레드가 쓰는 문단이 사라진다), 파일에 덧붙인 문단을 본문 끝에도 붙이고 맨 아래로 스크롤한다. 작업 스레드가 끝나면(멈추기 뒤 마지막 문단까지, 15초를 넘겨도) 본문을 파일과 맞추고 다시 쓸 수 있게 한다. 녹음 중인 기록은 옮기거나 지울 수 없다.
- `STT/`는 녹음 중 계속 덧붙으므로 라이브러리 감시에서 뺀다. 목록은 앱이 녹음을 시작하고 끝낼 때 다시 읽는다.
- 라이브러리가 열려 있어야 하고, 모델이 없으면 녹음할 때 안내하고 설정 창을 연다.
- 모델은 녹음이 끝나면 놓는다. 앱이 끝날 때까지 들고 있으면 종료 중 ggml Metal 장치 정리에서 멈춘다(GGML_ASSERT).
- 언어는 모델이 알아낸다(자동).
- 녹음 상태·파형은 gpui-kit `SpeechState`·`SpeechWaveform`을 쓰고, 인식기는 `SpeechRecognizer`로, 마이크는 cpal 0.18(rodio와 같은 판)로 `AudioInput`을 구현한다. 장치 표본율을 모노로 섞어 16 kHz로 낮춘다(저역 통과 후 선형 보간). 자동 음량 맞춤(기본 켬, 설정 → 받아쓰기)이 섞은 소리를 10 ms마다 보고 말소리(약 -20 dBFS)에 맞춰 최대 +24 dB까지 키운다. 키울 때는 천천히(약 1초), 줄일 때는 빨리, 넘치는 표본은 부드럽게 누르고, 약 -50 dBFS보다 조용한 구간(쉼의 잡음)에서는 더 키우지 않는다. 파형도 키운 소리로 보인다. 시스템 인식기로 넘어가지 않게 한다(Windows는 온라인 서비스다).
- 연산은 macOS가 Metal(정적 빌드), Windows가 Vulkan이다. Windows는 백엔드를 실행 중에 불러오는 빌드(transcribe-cpp `dynamic-backends`)라 Vulkan 드라이버가 없는 PC에서는 그 모듈만 건너뛰고 CPU로 돌고, CPU 모듈도 명령어 세트마다 따로 있어 빌드한 PC보다 오래된 CPU에서도 돈다(정적으로 Vulkan을 넣으면 `vulkan-1.dll`이 없는 PC에서 앱이 뜨지 않는다). 백엔드는 첫 모델을 불러오기 전에 메인 스레드에서 한 번 등록한다. ROCm은 HIP 런타임을 함께 실어야 하고 지원 GPU가 좁아 쓰지 않는다. 같은 녹음(91초)을 M5 Pro에서 재면 Nemotron이 Metal 1.4초·CPU 2.9초, Cohere(ADR-0056)가 Metal 2.0초·CPU 12.6초(4스레드 20.9초)였다.
- 소리는 기본으로 남기지 않는다. 설정의 "녹음 소리 남기기"(기본 끔)를 켜면 인식기에 넣는 소리(섞고 음량을 맞춘 16 kHz 모노 16비트)를 기록마다 `STT/.audio/<기록 ULID>.wav`로 남기고(이어서 녹음하면 끝에 잇는다), 고른 기록에 소리가 있으면 녹음 막대의 "녹음 듣기"로 시스템 앱에서 연다. 받아쓰기가 무엇을 들었는지 확인하고 같은 소리로 모델을 견주는 데 쓴다. 말없이 끝나 지운 새 기록은 소리도 지운다.
- macOS 번들 `Info.plist`에 마이크 사용 설명(`NSMicrophoneUsageDescription`)을 넣는다. 거부되어 있으면 시스템 설정에서 허용하라고 알린다.

## 결과 (Consequences)

- 좋아지는 점(+): 음성이 기기 밖으로 나가지 않고, macOS·Windows(·Linux)가 같은 엔진·품질이다. 다른 앱과 모델 파일을 함께 쓴다. 오래 켜 두어도 기록이 문단 단위로 바로 디스크에 쌓여, 앱이 죽어도 맺은 문단은 남는다.
- 감수하는 점(-): 모델이 716 MiB다. `hf-hub`(Xet 클라이언트 등)·transcribe.cpp(ggml, CMake 빌드)로 의존성과 빌드 시간이 늘었다. 받다가 멈추면 처음부터 다시 받는다. 문단은 쉼으로만 나눠 생각과 어긋날 수 있다. 녹음마다 모델을 다시 부른다(메모리 매핑이라 1초 안쪽). Windows 빌드에는 Vulkan SDK가 들고, 실행 파일 옆에 transcribe·ggml DLL(백엔드 모듈)을 함께 배포해야 한다.
- 후속 작업(TODO): LLM으로 요약(ADR-0055). 언어 고르기. 에디터에 바로 넣기. "새 문단" 같은 음성 명령.

## 대안 (Alternatives)

| 대안 | 기각 사유 |
| --- | --- |
| macOS `SFSpeechRecognizer` / Windows `SpeechRecognizer` | macOS는 긴 글에 약하고, Windows 자유 받아쓰기는 온라인 서비스다 |
| Whisper large-v3-turbo(whisper.cpp) | 스트리밍이 아니라 몇 초씩 끊어 늦게 보이고, 무음에서 글을 지어내 VAD가 필요하다. 파일도 더 크다 |
| Cohere Transcribe 03-2026(2B) | 한국어는 되지만 3배 크고 스트리밍이 아니다 |
| 양자화를 고르게 하기 | 일반 사용자에게 어렵다. Q8_0이 원본과 같은 정확도라 고를 이유가 적다 |
| 앱 전용 폴더에 모델 저장 | 이미 Hugging Face 캐시에 받아 둔 모델을 또 받게 된다 |
| 별도 받아쓰기 창 | 메인 창과 나란히 두기 어렵고, 기록 목록·에디터·끌어 옮기기를 따로 만들어야 한다 |
| 받아 적은 글을 열린 시트에 바로 넣기 | 오래 켜 두면 실행 취소·자동 저장·마크업과 얽히고, 시트를 바꾸면 끊긴다 |
| 녹음 하나를 스트림 하나로 끝까지 | 몇 시간이면 스트림의 글이 한없이 자라 매번 복사가 커진다 |
| gpui-kit `speech` 기능의 `Microphone` | cpal 0.15라 rodio(cpal 0.18)와 ALSA 링크가 겹쳐 빌드되지 않는다 |
| 클라우드 인식(Token Plan ASR, Amazon Transcribe) | 음성을 밖으로 보내지 않기로 했다 |
