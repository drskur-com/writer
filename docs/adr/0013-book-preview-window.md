# ADR-0013: 프로젝트 미리보기는 별도 창에서 자체 배치 엔진으로 PDF·ePub 페이지를 그린다

- 상태: Proposed
- 날짜: 2026-10-21
- 관련: ADR-0007, ADR-0009, ADR-0010, ADR-0012 · `src/app/book_preview/`, `src/library/manuscript.rs`, `src/markdown/book.rs`

## 배경 (Context)

Ulysses처럼 프로젝트(책)를 내보내기 전에 결과를 PDF·ePub 기준으로 미리 보고 싶다. 쓰는 창은 그대로 두고 옆에 띄워 볼 수 있어야 한다.
내보내기(M7)는 아직 없고, gpui에는 PDF·HTML 렌더러가 없다. 마크다운 프리뷰(`TextView::markdown`)는 쪽 나눔·양쪽 정렬·책 스타일을 모른다.

## 결정 (Decision)

**미리보기는 프로젝트마다 별도 창 하나로 연다. 원고를 책 블록으로 바꾼 뒤 gpui 글자 측정으로 직접 줄바꿈·쪽 나눔을 해서 페이지를 그린다.**

- 여는 곳: 프로젝트 화면 도구 줄의 미리보기(눈) 버튼. 열린 시트를 먼저 저장한다. 이미 열려 있으면 그 창을 앞으로 가져온다.
- 원고(`library::manuscript_sheets`): 프로젝트 바로 아래 시트 → 원고 그룹(메타 `groups` 순서, 그룹마다 자기 시트 → 하위 그룹). 추가자료는 빠진다.
  접합하지 않은 시트는 새 페이지에서 시작하고, 접합한 시트는 앞 시트에 이어진다(ADR-0012 후속).
- 블록(`markdown::blocks`): 같은 파서(markdown-rs)로 제목·문단·인용·목록·코드·표·구분선·이미지(ADR-0007 속성)·각주(시트 끝에 모음)를 만든다.
- 배치(`book_preview/layout.rs`): 배율 1 단위(PDF 1pt, ePub CSS 1px)로 계산하고 그릴 때만 배율을 곱한다.
  - 줄바꿈은 문단을 한 줄로 shape한 뒤 글자 위치로 나눈다. 공백, 그리고 한글·한자·가나는 글자 사이에서 나눌 수 있다(에디터 줄바꿈과 같다). 닫는 부호는 앞 글자에, 여는 부호는 뒤 글자에 붙인다.
  - 양쪽 정렬은 마지막 행을 뺀 행의 공백 묶음에 남는 폭을 나눈다(ADR-0010과 같은 규칙).
  - 블록 사이 여백은 max(앞 뒤 여백, 뒤 앞 여백), 페이지 첫머리에서는 없앤다. 제목 뒤 첫 줄은 제목과 함께 두고, 세 줄 이하 문단은 나누지 않으며, 외톨이·과부 줄을 피한다.
  - 제목 배치(ADR-0009): 별도 제목 페이지는 세로 위치대로 혼자 놓고, `page_break`는 새 페이지, 숨김은 그리지 않고 차례에만 남긴다. 접두사 `{n}`은 대상별 번호.
  - 전면 이미지(`.full-page`)는 전용 페이지에 칸 안에 맞춘다.
- PDF: 판형(신국판·A5·4·6판·A4·Letter)과 판형별 여백·본문 크기. 표지(판형을 채움) → 속표지 → 인쇄 차례(쪽 번호) → 본문. 본문 첫 페이지가 1쪽이고, 제목 페이지·전면 이미지에는 쪽 번호를 찍지 않는다. 서체는 늘 스타일 서체(PDF에는 서체가 들어간다). 확대 50~200%.
- ePub: 휴대폰·태블릿 화면 크기로 페이지를 나누고(기기 테두리 없이 페이지만) 한 장씩 넘긴다(버튼·좌우 절반 클릭·←/→). 표지(화면 안에 맞춤) → 속표지 → 본문, 인쇄 차례는 없고 차례 메뉴로 이동한다. 서체를 넣지 않으면(`embed_font = false`) 리더 기본 서체(시스템 서체)로 그린다.
- 프로젝트 폴더를 감시해 시트(자동 저장 포함)·스타일·책 정보가 바뀌면 다시 읽어 배치한다. 에디터 서체 설정이 바뀌어도 다시 배치한다.
- 종이는 앱 테마와 상관없이 흰 바탕에 검은 글자다.

## 결과 (Consequences)

- (+): 판형·화면 크기에 따른 쪽 나눔, 양쪽 정렬, 제목 배치, 차례·쪽 번호를 실제 책처럼 볼 수 있다. 외부 렌더러(WebKit·PDF 엔진) 없이 gpui만 쓴다.
- (+): 블록 변환과 원고 순서는 gpui를 쓰지 않아 내보내기(M7)가 그대로 쓸 수 있다. 줄바꿈은 측정 함수를 받아 gpui 없이 테스트한다.
- (-): 미리보기는 실제 PDF·ePub 파일이 아니다. 내보내기 엔진(typst, 리더)과 줄바꿈·쪽 나눔이 조금 다를 수 있다. 내보내기를 만들면 같은 규칙을 맞추거나, PDF는 만든 파일을 그려 보이는 쪽으로 바꾼다.
- (-): 배치는 UI 스레드에서 한 번에 한다(원고·판형이 바뀔 때만). 아주 긴 원고에서는 다시 읽을 때 잠깐 멈출 수 있다.
- (-): 표 행·코드 줄은 페이지에서 나누지 않고, 하이픈 넣기·자간 조정은 없다. 미리보기 판형·확대는 창을 닫으면 잊는다.
- 후속(TODO):
  - 내보내기(M7)에서 `markdown::blocks`·`manuscript_sheets`를 쓰고 배치 규칙을 맞춘다.
  - 에디터 커서 위치의 페이지로 바로 가기, 미리보기 판형을 프로젝트에 기억하기.
  - 긴 원고는 배치를 백그라운드로 옮긴다(`TextSystem`만으로 측정).

## 대안 (Alternatives)

| 대안 | 기각 사유 |
| --- | --- |
| typst로 실제 PDF를 만들고 PDFKit으로 그림 | 내보내기 엔진·서체 번들이 먼저 필요하고 macOS 전용이다. ePub은 여전히 따로 그려야 한다 |
| `TextView::markdown`으로 이어진 한 장 | 쪽 나눔·양쪽 정렬·제목 페이지를 보일 수 없다 |
| 메인 창 오른쪽 프리뷰 칸 | 판형 페이지를 보기에 좁고, 쓰는 화면과 따로 띄워 둘 수 없다 |
| 시트 경계를 무시하고 이어 붙임 | 접합(ADR-0012)의 뜻이 없어진다 |
