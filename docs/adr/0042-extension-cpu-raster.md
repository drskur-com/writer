# ADR-0042: 확장의 모양 목록은 vello_cpu로 픽셀 이미지에 그려 화면·PNG에 같이 쓴다

- 상태: Proposed
- 날짜: 2026-10-23
- 관련: ADR-0026(Lua 확장, 화면 그리기 부분을 대체), ADR-0038(플레이 창) · `src/extension/render.rs`, `src/extension/raster.rs`, `src/app/extension_painter.rs`

## 배경 (Context)

ADR-0026의 화면 그리기는 모양마다 lyon으로 삼각형을 만들어 GPUI `paint_path`로 칠했다. GPUI의 경로 칠은 두 색 선형
그라디언트뿐이라 세 색 이상은 띠로, 방사형은 고리 × 부채꼴 칸으로 근사했고, 경로 자르기는 삼각형끼리의 교집합, 글자는
테두리 상자로만 잘랐다. 어시스턴트가 보는 PNG는 따로 tiny-skia로 그려 화면과 결과가 달랐다. 블러·블렌드·이미지는
GPUI 경로로는 만들 수 없다.

GPUI는 외부 GPU 텍스처를 받지 않으므로(macOS의 `paint_surface`만 예외) 다른 렌더러는 CPU로 그려 이미지로 올려야
한다. 측정(1200×800px, 반투명 원, 방사형 세 색, release, Apple Silicon):

| 모양 | tiny-skia | vello_cpu(한 스레드) |
| --- | --- | --- |
| 500 | 31.6ms | 3.4ms |
| 2000 | 127ms | 13.5ms |

라이브러리 예제 확장은 2배 해상도에서 래스터 0.1~0.9ms, BGRA 변환 0.3~0.5ms였다. 앱 안에서 잰 그림 한 장(래스터 + 변환 +
이미지)은 둠 플레이 창 1600×1000px 평균 2.7ms, 애니메이션 블록 1272×1336px 평균 4.3ms(최대 6.4ms)다.

## 결정 (Decision)

**모양 목록은 그대로 두고, 화면·PNG·DOCX가 모두 `extension::render`(vello_cpu)로 픽셀을 만든다.**

- `Renderer`는 모양을 캔버스 좌표 × 배율로 그린다. 그라디언트는 vello의 선형·방사형(멈춤 여럿, 바깥은 끝 색)을 그대로 쓰고,
  `Clip`·`ClipPath`는 자르기 경로로 건다(바뀌면 모두 풀고 다시 건다). 글자는 시스템 서체 윤곽(PDF와 같은 이름 목록)이라
  경로로도 잘린다. 한 스레드로 돈다(vello의 필터는 여러 스레드와 함께 쓰지 못한다).
- 화면(`extension_painter`): 캔버스마다 마지막 이미지를 (모양 열쇠, 기기 픽셀 크기)로 기억해 같으면 다시 쓴다. 바꾼 이미지와
  사라진 캔버스의 이미지는 그 창의 아틀라스에서 지운다(창이 있어야 해서 다음에 그 창을 그릴 때). 한 변은 8192px까지이고
  넘으면 해상도를 낮춘다. 개발 빌드는 그림 한 장이 8ms를 넘으면 알린다.
- PNG(`raster`): 격자의 칸마다 같은 렌더러로 그린다. tiny-skia는 뺐다.
- 서체는 앱을 열 때 작업 스레드에서 미리 찾는다(처음 한 번 약 0.2초).
- PDF(krilla)·ePub(SVG)는 벡터 그대로 둔다.

## 결과 (Consequences)

- (+): 화면과 어시스턴트가 보는 그림이 같다. 그라디언트와 경로 자르기가 근사가 아니다. 삼각형·칸 근사 코드가 빠졌다.
- (+): 블러·그림자, 블렌드, 이미지, 3차원 깊이 버퍼처럼 GPUI 경로로 못 하던 것을 같은 경로에 더할 수 있다.
- (-): 그리기는 GPU 대신 UI 스레드의 CPU가 한다. 애니메이션은 프레임마다 다시 그려 올린다(위 측정, 블록 수만큼 는다).
  애니메이션 모양 상한(2천)은 그대로 둔다.
- (-): 글자는 서체 윤곽이라 커닝·합자·힌팅이 없다. 화면 글자가 GPUI 글자와 조금 다르다.
- (-): 이미지 크기가 바뀌면(확대, 창 크기) 다시 그린다.
- 후속(TODO): 캔버스 API에 블러·그림자·블렌드·이미지·글자 회전, 3차원을 깊이 버퍼 래스터로, 그리기를 작업 스레드로 옮기기.

## 대안 (Alternatives)

| 대안 | 기각 사유 |
| --- | --- |
| GPUI 경로 유지, 셰이더에 방사형·여러 멈춤 패치 | 자르기·블러·블렌드는 여전히 안 되고, vendor 패치를 계속 들고 간다 |
| tiny-skia(이미 쓰던 것) | 모양 500개부터 한 프레임(33ms) 안에 못 그린다 |
| skia-safe | 기능은 가장 넓지만 빌드가 무겁고 바이너리가 크게 는다. 지금 필요한 것은 vello_cpu로 된다 |
| ThorVG, Blend2D, Cairo | C/C++ 빌드와 어린(또는 멈춘) Rust 바인딩, Cairo는 LGPL과 느린 속도 |
| CoreGraphics / Direct2D | 플랫폼마다 따로 만든다 |
| vello(GPU)·wgpu | GPUI와 GPU 장치를 함께 쓸 수 없어 읽어 와야 한다 |
