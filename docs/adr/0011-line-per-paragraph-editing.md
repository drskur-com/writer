# ADR-0011: 에디터에서는 줄 하나가 문단이고, 파일에는 표준 마크다운으로 변환해 저장한다

- 상태: Proposed
- 날짜: 2026-10-20
- 관련: ADR-0010 · `src/text_transform.rs`, `src/app/editor.rs`

## 배경 (Context)

표준 마크다운에서는 빈 줄이 문단을 나눈다. `A\nB`는 한 문단("A B")이고, 빈 줄은 몇 개든 문단 경계 하나가 된다(markdown-rs로 확인).

- `A\n\n\nB` → `<p>A</p><p>B</p>`. 추가 빈 줄은 HTML에 남지 않고, 문단 간격은 CSS가 정한다.

글쓰기 화면에서는 Enter 한 번이 새 문단인 편이 자연스럽다(Ulysses·iA Writer와 같은 경험). 그런데 그 줄바꿈을 그대로 저장하면 다른 마크다운 앱에서 문단이 합쳐진다.
Ulysses 도움말도 "빈 줄은 서식에 영향을 주지 않고, 문단 간격은 내보내기 스타일로 정한다"고 안내한다.

## 결정 (Decision)

**에디터 버퍼에서는 줄 하나가 문단이다. 시트를 열 때 마크다운을 에디터 본문으로, 저장할 때 다시 표준 마크다운으로 바꾼다.**

| 에디터 | 파일(마크다운) |
| --- | --- |
| `A⏎B`(문단 두 개) | `A\n\nB` |
| `A⏎⏎B`(빈 행 1개) | `A\n\n\nB` |
| 빈 행 k개 | 빈 줄 k+1개 |

- 추가 빈 줄은 **표준대로 버린다**. 다른 앱과 우리 내보내기에서는 문단 경계 하나로 보이고, 이 앱으로 다시 열 때만 빈 행이 돌아온다. 장면 전환처럼 의도적인 공백은 구분선(`***`)으로 쓴다.
- 줄바꿈 하나로 이어져야 하는 줄에는 빈 줄을 넣지 않는다. 목록 항목끼리(들여쓴 하위 줄 포함), 인용 줄끼리, 표 행끼리, 4칸 들여쓴 줄끼리, 줄 끝 강제 줄바꿈(공백 두 칸·`\`) 뒤, setext 밑줄 앞이 그렇다.
- 코드·수식 펜스(```` ``` ````·`~~~`·`$$`)와 문서 첫 줄의 frontmatter(`---`) 안은 한 글자도 바꾸지 않는다. 닫히지 않은 펜스는 문서 끝까지 그대로 둔다.
- 문서 처음과 끝의 빈 줄은 변환하지 않는다.
- 다른 앱에서 만든 파일의 문단 안 줄바꿈(`A\nB`)은 읽을 때 공백으로 이어 한 줄(`A B`)로 만든다. 의미는 같지만 저장하면 줄 모양이 바뀐다.
- 파일은 내용을 고쳤을 때만 저장한다(열기만 하면 그대로).
- 변환은 줄 단위 상태 기계로 한다(펜스만 따라가면 된다). 전체 파서는 쓰지 않는다.

## 결과 (Consequences)

- (+): 쓰는 경험은 "Enter = 새 문단"이고, 파일은 다른 마크다운 앱에서도 문단이 그대로 보인다.
- (+): 에디터 본문 → 마크다운 → 에디터 본문이 원래대로 돌아온다. 14종류의 줄을 네 줄까지 모든 순서로 섞은 조합(약 4만 1천 개, 끝 줄바꿈 유무까지 약 8만 3천 경우)을 테스트로 지킨다.
- (-): 다른 앱에서 만든 파일은 처음 고쳐 저장할 때 문단 안 줄바꿈이 공백으로 바뀌고, 느슨한 목록(항목 사이 빈 줄)은 빈 행이 생긴다.
- (-): 에디터의 마크업 표시(`markdown::spans`)는 에디터 본문을 파싱하므로, 표준 해석과 미세하게 다를 수 있다(예: 이어진 두 줄이 한 문단으로 파싱됨). 인라인 표시에는 영향이 없다.

## 대안 (Alternatives)

| 대안 | 기각 사유 |
| --- | --- |
| 입력한 줄바꿈 그대로 저장(줄바꿈 하나 = 문단으로 우리만 해석) | 다른 마크다운 앱에서 문단이 합쳐진다 |
| 마크다운 원문 그대로 편집(빈 줄로 문단 구분) | 문단마다 빈 줄을 두 번 쳐야 하고, 빈 줄을 접으면 커서 이동마다 레이아웃이 움직인다 |
| 추가 빈 줄을 빈 문단(`&nbsp;`)으로 저장해 책에도 남김 | 원문이 지저분해지고 표준 렌더링과 어긋난다 |
| markdown-rs 전체 파싱으로 변환 | 줄 단위 왕복 보존이 어렵고(파서는 원문 공백을 버림), 펜스 추적만으로 충분하다 |
