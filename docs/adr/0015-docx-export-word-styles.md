# ADR-0015: DOCX는 원고 블록을 Word 스타일 문서로 만든다(미리보기 배치를 옮기지 않는다)

- 상태: Proposed
- 날짜: 2026-10-21
- 관련: ADR-0009, ADR-0012, ADR-0014 · `src/export/docx.rs`, `src/app/compile_dialog.rs`

## 배경 (Context)

DOCX 내보내기가 필요하다. 받는 사람(편집자·출판사)은 문서를 고쳐 쓴다. DOCX는 흐르는 문서라 쪽 나눔·줄바꿈은 Word가 한다.
PDF처럼 미리보기 좌표를 옮기면 글상자로 된, 고칠 수 없는 문서가 된다.

## 결정 (Decision)

**ePub처럼 원고 블록(`manuscript_blocks`)을 Word 구조로 바꾸고, 책 스타일은 Word 스타일로 둔다. zip + 직접 쓴 OOXML(새 의존성 없음).**

| 책 스타일 | DOCX |
| --- | --- |
| 본문 서체·크기·줄 간격·정렬·들여쓰기·간격 | 단락 스타일 Normal(문서 기본값 포함) |
| 부·장·절 | Heading1~3(개요 수준 0~2). 목차에서 뺀 제목은 단락에서 개요 수준 9(본문) |
| 새 페이지에서 시작 | 스타일의 `pageBreakBefore` |
| 별도 제목 페이지·세로 위치 | 구역 나누기 + 구역 `vAlign`(제목 구역은 쪽 번호 없음) |
| 제목 숨김 | 쓰지 않음(쪽 나눔만 남음) |
| 접두사·번호 | 계산한 글자(개행은 줄바꿈). Word 자동 번호는 쓰지 않는다 |
| 목차 생성 | Word 목차 필드 `TOC \o "1-3"`, 열 때 갱신(`updateFields`) |
| 각주 | Word 각주. 본문의 위 첨자 번호 자리가 참조가 된다 |
| 이미지·캡션 | 인라인 그림(크기 속성 px → pt, 본문 폭·높이에 맞춤) + Caption 스타일. WebP 등은 PNG로 바꾸고 SVG는 넣지 않는다 |
| 표 | 표(머리 행 굵게·반복), 목록은 기호 + 내어쓰기 단락, 코드는 고정폭 Code 스타일 |
| 표지·책 정보 | 첫 구역에 표지 그림(본문 칸에 맞춤), 속표지(Title·Subtitle), `core.xml`에 제목·지은이·언어·소개 |
| 판형 | 컴파일 대화상자에서 고른 판형(PDF와 같은 크기·여백·본문 크기) |
| 시트 접합 | 접합하지 않은 시트는 새 페이지(`pageBreakBefore`) |
| 쪽 번호 | 본문 구역 꼬리말 가운데 `PAGE` 필드, 본문 첫 구역에서 1부터 |

- 서체는 이름만 적는다(Word 서체 넣기는 하지 않는다). 스타일에 서체가 없으면 설정의 에디터 서체, 시스템 내부 이름이면 적지 않는다.
- OOXML은 자식 요소 순서를 스키마대로 써야 Word가 연다(단락·글자·구역 속성, settings).

## 결과 (Consequences)

- (+): 받는 사람이 Word 스타일만 고쳐 문서 전체 모양을 바꿀 수 있다. 탐색 창·목차·각주가 Word 기능 그대로 동작한다.
- (+): 각주가 같은 쪽 아래에 놓인다(ePub·PDF보다 낫다).
- (-): 쪽 나눔은 Word가 하므로 미리보기·PDF와 쪽이 다르다. 미리보기 창에 DOCX 보기는 없다.
- (-): 받는 쪽에 서체가 없으면 Word가 다른 서체로 보인다. 표지는 여백 안에 놓인다(판형을 채우지 않는다).
- (-): 목차 쪽 번호는 Word가 열 때 필드를 갱신해야 채워진다(갱신 여부를 묻는 창이 뜬다).

## 대안 (Alternatives)

| 대안 | 기각 사유 |
| --- | --- |
| 미리보기 배치를 글상자로 옮김 | 고칠 수 없는 문서가 된다 |
| `docx-rs` 크레이트 | 구역 세로 맞춤·필드 같은 세부 설정에서 막히기 쉽다. 직접 쓰는 OOXML이 epub.rs와 같은 방식이다 |
| Word 자동 번호(numbering.xml)로 접두사 | `제{n}장` 같은 접두사·로마 숫자·개행 처리를 그대로 옮기기 어렵고 고칠 때 깨지기 쉽다 |
