# ADR-0026: 확장은 라이브러리의 Lua(Luau) 스크립트로 두고, 시트의 `` ```ext `` 블록에 캔버스로 그리거나 메뉴 명령을 더한다

- 상태: Proposed (화면 그리기는 Superseded by ADR-0042, 3차원 그리기는 ADR-0045)
- 날짜: 2026-10-23
- 관련: ADR-0008(줄 블록), ADR-0017(표: 접힌 줄 + 아래 블록), `src/extension/`, `src/app/editor_extension.rs`, `src/app/extension_painter.rs`, `src/app/extension_commands.rs`, `src/app/insert_extension.rs`, `src/app/manage_extensions.rs`, `src/agent/tools.rs`(`run_extension`), `src/extension/raster.rs`, `src/agent/prompt.rs`, `resources/skills/extension/`

## 배경 (Context)

간단한 기능을 앱을 고치지 않고 더하고 싶다. 예를 들면 시트 안에 그림이나 애니메이션(궁수가 활을 쏜다)을
넣거나, 오늘 날짜를 넣는 명령 같은 것이다. 코드는 사용자가 아니라 어시스턴트가 스킬을 따라 쓴다.

- 외부 런타임(Node, Python)에 기대지 않고 앱에 넣을 수 있어야 한다.
- 모델이 쓴 코드가 한 번에 맞지 않아도 스스로 실행해 보고 고칠 수 있어야 한다.
- 남이 쓴 코드가 될 수 있으니 파일·네트워크에 닿지 못하고, 무한 루프에도 앱이 멈추지 않아야 한다.
- 나중에 그림을 PDF·EPUB·DOCX에도 넣을 수 있어야 한다.

## 결정 (Decision)

**확장은 `Extensions/<이름>.lua` 하나이고, mlua의 Luau sandbox에서 돈다. 파일은 표를 돌려주고, 앱은 그 안의
진입점만 쓴다.**

- 진입점(앱이 정한 자리, 내용은 확장이 정한다):
  - `draw(g, t, args)`: 시트의 `` ```ext <이름> `` 펜스(본문은 `key: value` 인자) 자리에 그린다. `size = {w, h}`
    캔버스, `animated = true`면 보이는 동안 매 프레임 부른다(`t`는 초).
  - `commands = { { title, run(ctx) } }`: `Extensions` 메뉴의 명령. 돌려준 글로 선택 영역을 바꾼다(없으면 커서 자리).
- 캔버스 `g`는 LÖVE `love.graphics`의 이름·인자를 따른다(`setColor`, `rectangle`, `circle`, `arc`, `line`,
  `polygon`, `print`, `printf`, `push`/`pop`/`translate`/`rotate`/`scale` 등). 호출은 **모양 목록**(경로·글자,
  캔버스 좌표, 원·호는 3차 베지어)으로 모으고, 에디터는 GPUI `canvas`에서 `paint_path`·`shape_line`으로 그린다.
  없는 함수를 부르면 쓸 수 있는 목록을 알린다.
- 벡터(LÖVE에 없는 것): `g.newPath([svg])`(빌더 `moveTo`·`curveTo`·`quadTo`·`arc`…, SVG 경로 문자열 `M L H V C S Q T A Z`),
  `g.fill`·`g.stroke`, 그라디언트(`g.newLinearGradient`·`g.newRadialGradient`를 `setColor`에), `setLineJoin`·`setLineCap`·
  `setMiterLimit`·`setDash`(offset 포함)·`setFillRule`(nonzero·evenodd)·`setScissor`(사각형 자르기)·`setClip`(경로 자르기), 경로 측정
  (`length`·`pointAt`·`trim`·`bounds`), 제어점(`points`·`withPoints`)과 모핑(`g.lerpPath`), `g.ease.*`·`g.lerp`·`g.lerpColor`.
  - 불리언(`union`·`subtract`·`intersect`·`xor`), 선 윤곽(`outline`), 넓히기·좁히기(`offset`)는 작업 스레드에서 i_overlay로
    한다. 곡선을 펴서 연산하므로 결과는 다각형이다(모핑 구조가 바뀐다).
  - 경로 자르기는 화면에서 모양의 삼각형과 자르는 경로의 삼각형이 겹친 곳(볼록 ∩ 볼록)만 남긴다. 테셀레이션 결과는
    서로 겹치지 않아 반투명도 두 번 칠해지지 않는다. 글자는 GPU 글자라 그 영역의 테두리 상자로만 자른다.
  - 경로는 지역 좌표로 두고 그릴 때 변환을 적용한다. 그래서 파일 맨 위에서 한 번 만들어 여러 번 그린다. `g`는 로드할 때도
    전역으로 있다(sandbox가 얼리지 않게 sandbox 뒤에 넣는다).
  - 측정·자르기·점선은 작업 스레드에서 lyon 경로 측정으로 한다. 곡선은 잘라도 곡선이다. 점선은 기록할 때 경로를 나눠 둔다.
  - 모양 목록: `Fill { path, paint, rule }`, `Stroke { path, paint, style }`, `Clip(rect)`. `paint`는 단색·선형·방사형
    (캔버스 좌표, 멈춤 여럿). 내보내기는 이것을 그대로 PDF·SVG 그라디언트로 옮길 수 있다.
  - 화면(`src/app/extension_painter.rs`): 모양마다 lyon으로 삼각형을 만들고 (모양, 배율)로 캐시한다. GPUI의 경로
    그라디언트는 두 색 선형이고 경로의 테두리 상자 기준이라, 두 점 사이 그라디언트를 상자 기준 각도·자리로 바꿔 준다
    (셰이더 식을 옮긴 테스트로 맞는지 본다). 세 색 이상은 삼각형을 멈춤 사이 띠로 잘라 정확히, 방사형은 고리 × 부채꼴
    칸(현의 오차 0.25px 안)으로 잘라 칸마다 반지름 방향 두 색으로 근사한다.
- 3차원: `g.newScene([x, y, w, h])`이 장면을 돌려준다. 카메라(`camera`·`ortho`), 빛(`light`), 3차원 변환,
  입체(`box`·`sphere`·`cylinder`·`cone`·`torus`·`plane`·`polygon`·`mesh`)와 `line`을 모았다가 `draw()`에서 투영해,
  면마다 평면 음영(주변광 + 램버트)을 준 2차원 다각형으로 모양 목록에 넣는다. GPU는 쓰지 않는다. 가림은 면의
  평균 깊이로 줄 세우는 화가 알고리즘이고, 닫힌 입체의 뒷면은 버린다. `project`는 3차원 점의 캔버스 위치를 알려
  글자를 붙이게 한다. 이웃한 면 사이 안티에일리어싱 틈은 불투명한 면을 0.35만큼 넓혀 가린다.
- 에디터: 펜스 줄은 표처럼 접고(`collapsed`·`reveal_run`) 닫는 줄 아래 줄 블록에 캔버스를 그린다. 본문 폭보다
  크면 비율을 지켜 줄인다. 읽기·그리기 오류는 블록 자리에 보인다. 확장 파일이 바뀌면 다시 읽는다.
- 실행 위치: 확장마다 작업 스레드 하나가 Lua 상태를 들고 `draw`를 돌린다. 에디터는 요청만 보내고 마지막으로 받은
  결과를 그리며, 기다리는 요청이 있으면 새로 보내지 않는다. 그래서 느린 확장은 그 블록만 늦게 바뀌고 편집은 막히지
  않는다. 파일 읽기는 UI 스레드가 기다린다(배치에 캔버스 크기가 필요하다). 크기는 코드(`size`)에 둔다. `size`가
  `function(args)`면 블록 인자마다 한 번 작업 스레드에 묻고 답을 기다린다(인자별로 캐시).
  - 블록 인자 `scale:`(0.1~4)은 앱이 읽는 예약어다. 캔버스를 그 배율로 키워 그리고(본문 폭까지), 확장에는 넘기지
    않는다. 그래서 모든 확장이 따로 구현하지 않아도 크기를 바꿀 수 있다.
  - 애니메이션은 초당 30번 다시 그리고, 창이 비활성이거나 움직임 줄이기 설정이면 멈춘다.
  - `period`(초, 10 이하)가 있으면 `t`가 한 주기를 되풀이한다. 처음에는 한 주기의 프레임을 캐시했으나, `draw`가 프레임당
    0.1ms 안팎이라(release, 예제 확장) 보관하지 않고 매번 그린다. 같은 모양의 삼각형은 다시 쓴다.
  - 애니메이션 한 프레임의 모양은 2천 개까지다. 모양을 삼각형으로 나누고 그리는 일은 UI 스레드에 남기 때문이다.
- sandbox: Luau 기본(`io` 없음, `os`는 시간 함수뿐) + `require` 제거(폴더 확장의 모듈만 부르는 `require`는 ADR-0039) + `sandbox(true)`. 메모리 64MB, 시간은 읽기 0.1초·
  그리기 0.1초·명령 2초(interrupt로 끊는다). `math.random`은 그릴 때마다 같은 seed로 되돌린다.
- 앞머리: 확장 파일은 Lua 블록 주석 `--[[---` … `---]]`으로 시작하고, 안에 `description`, `args`(인자마다 설명),
  `example`(미리보기·넣기용 값)을 `key: value`로 적는다. Lua를 돌리지 않고 읽는다.
  - **설명과 인자 설명은 사용자의 언어로 쓴다.** 사용자에게 보이는 글이라, 모델이 읽는 글을 영어로 쓰는 규칙의 예외다.
  - Insert → Extension… 대화상자가 그림을 그리는 확장을 앞머리로 나열한다. 인자마다 입력 칸이 있고 처음 값은
    `example`이다. 값을 고치면 실제 `draw`로 미리보기를 바로 다시 그리고, 삽입하면 그 값으로 블록을 커서 자리에
    넣는다(빈 칸은 빼서 확장의 기본값을 쓴다).
  - 시스템 프롬프트에 `<extensions>` 목록(이름·인자 이름·설명)을 넣어, 있는 확장을 새로 만들지 않고 쓰게 한다.
  - `run_extension`은 앞머리가 없거나, 설명이 없거나, 인자가 `args`에 없으면 알린다.
- 관리: `Extensions` 메뉴는 명령이 없어도 늘 있고, 맨 아래 `Manage Extensions…` 대화상자가 모든 확장(그림·명령·읽지
  못하는 것)을 목록으로 보이고, 고른 것의 미리보기(`example` 인자, 삽입 대화상자와 같은 그리기)나 명령 목록,
  설명, 쓰는 시트 수를 보인다. Finder에서 보기와 휴지통으로 이동이 있다. 지우기 전에
  쓰는 시트 수를 알리고, 원고의 블록은 건드리지 않는다(블록 자리에 확장이 없다고 보인다).
- 어시스턴트: 빌트인 스킬 `extension`(API·규칙)과 `run_extension` 도구(그리기 결과의 모양 수·범위, 명령 결과,
  오류)를 준다.
  - 그리기 결과는 그림(PNG)으로도 붙여 모델이 직접 본다(`src/extension/raster.rs`, tiny-skia). 숫자만으로는 모양이
    어색한지 알 수 없어서다. 밝은 테마, 캔버스 크기로 자르고, 긴 변 1568px 안에서 최대 2배로 그린다. 글자는 시스템
    서체(PDF 내보내기와 같은 이름 목록) 윤곽이라 화면과 폭이 조금 다를 수 있다. `times`(8개까지)를 주면 여러 프레임을
    `t = …` 이름표와 함께 격자로 한 장에 넣는다. 이미지를 넣는 자리는 web_fetch와 같다(ADR-0028). 파일은 기존 `write_file`·`edit_file`(승인 diff)로 쓴다. 라이브러리를 열 때 `Extensions/`를 만든다.

## 결과 (Consequences)

- (+): 의존성은 mlua(Luau 소스를 정적으로 빌드) 하나다. 외부 런타임이 없다.
- (+): 모양 목록은 출력 형식과 상관없어서, 같은 확장을 PDF(krilla 경로)·EPUB(SVG)·DOCX(SVG+PNG)로 옮길 수 있다.
- (+): 펜스라서 다른 마크다운 앱에서는 코드 블록으로 보이고 원고가 깨지지 않는다.
- (-): Lua 문자열은 바이트라 한글을 자르거나 셀 때 `utf8.*`를 써야 한다(스킬에 적었다).
- (-): 캔버스는 LÖVE의 일부뿐이다(이미지·셰이더·입력 없음). 글자는 돌리지 않는다.
- (-): 3차원은 면 단위 깊이 정렬이라, 서로 뚫고 지나가는 면이나 큰 면 옆의 작은 면은 순서가 틀릴 수 있다(깊이 버퍼 없음). 면 하나가 모양 하나라 모양 상한(애니메이션 2천)이 장면 크기를 정한다.
- (+): 3차원 결과도 2차원 모양 목록이라 내보내기 경로가 그대로 쓰인다.
- (+): 삼각형 캐시로 정지 그림, 주기 애니메이션의 같은 프레임, 움직이지 않는 모양은 다시 나누지 않는다.
- (-): 방사형 그라디언트는 화면에서 근사라 칸이 많다(큰 원은 수백 조각). 블렌드·블러는 없다. 경로 자르기는 (모양 삼각형 × 영역 삼각형)만큼 들지만 캐시한다.
- (-): 애니메이션 블록이 보이면 창 전체를 초당 30번 다시 그린다. 블록 수보다 이 고정 비용이 크다(디버그 빌드에서 CPU 약 13%).
- (-): 블록이 처음 보일 때 첫 결과가 올 때까지(수 ms) 캔버스가 비어 있다.
- (-): 앞머리와 코드가 어긋날 수 있다(인자를 바꾸고 `args`를 고치지 않는 등). 스킬과 `run_extension`의 알림으로 줄인다.
- 내보내기: 책 미리보기와 PDF는 확장 블록을 그림으로 넣는다. 원고를 읽을 때 블록마다(같은 이름·인자는 한 번) 밝은 테마의
  `t = 0` 프레임을 그려 두고(`extension::still`), 배치는 캔버스 × `scale:`을 이미지 px처럼 판형 단위로 바꿔 가운데 둔다
  (본문 폭·페이지보다 크면 줄인다). 미리보기는 에디터와 같은 painter로, PDF는 모양 목록을 krilla 벡터(경로·선·그라디언트·
  자르기·글자)로 그린다. ePub은 블록마다(같은 이름·인자는 한 번) SVG 파일(`src/extension/svg.rs`, 크기는 캔버스 × `scale:` px,
  그라디언트는 `userSpaceOnUse`, 자르기는 `<g clip-path>`, 글자는 리더의 sans-serif)을 넣고 가운데 그림으로 둔다. 그리지 못하면
  (확장 없음·그림 없는 확장·오류) 예전처럼 코드 블록이다. DOCX는 같은 그림을 PNG(캔버스 px의 3배, tiny-skia)로 넣고
  `asvg:svgBlip`으로 SVG를 함께 단다. Word 2016 이상은 SVG를 벡터로, 다른 앱은 PNG를 보인다.
- 후속(TODO): 내보내기(`still:` 인자의 프레임), 미리보기 창, 인라인 값(ADR-0036), 블록 입력(키보드·끌기), 확장 설정 화면. 호버·클릭은 ADR-0032.

## 대안 (Alternatives)

| 대안 | 기각 사유 |
| --- | --- |
| JS(rquickjs) | 문자열·정규식은 낫지만, 캔버스 API를 흉내 낼 기준(LÖVE)이 Lua 쪽에 있고 sandbox·시간 제한은 Luau가 더 간단하다 |
| Rhai, Lisp(Steel·Janet) | 모델이 잘 모르는 언어라 실패가 잦다 |
| WebAssembly(wasmtime·wasmi) | 확장마다 컴파일러가 필요하다. 배포용 확장 생태계에 맞고, 모델이 바로 쓰는 스크립트에는 무겁다 |
| 설명을 돌려주는 표에 둔다(`description = ...`) | 목록·프롬프트를 만들 때마다 모든 확장을 실행해야 한다. 앞머리는 읽기만 하면 된다 |
| 확장이 SVG 문자열을 돌려준다 | 매 프레임 SVG를 파싱·래스터화해 아틀라스에 올려야 한다. 그리는 코드를 직접 쓰는 캔버스보다 덜 자연스럽다 |
