# ADR-0038: 상태·키보드·게임 루프가 필요한 확장은 `play` 표로 두고 따로 연 창에서 실행한다

- 상태: Proposed
- 날짜: 2026-10-23
- 관련: ADR-0026(Lua 확장), ADR-0032(호버·클릭), ADR-0035(동작) · `src/extension/worker.rs`(`PlayWorker`, `PlayEvent`), `src/extension/mod.rs`(`play_size`·`play_load`·`play_call`·`play_draw`), `src/app/play_window.rs`

## 배경 (Context)

블록의 `draw`는 상태가 없는 함수이고(같은 `t`·인자면 같은 그림), 내보내기에 들어가며, 마우스는 영역 호버·클릭만 받는다
(ADR-0032). 간단한 게임처럼 상태를 들고, 키보드를 받고, 매 프레임 도는 것을 원고 블록 안에서 하면 에디터 키 입력과 겹치고,
창 전체를 계속 다시 그리며, 내보내기에 의미 없는 상태가 섞인다.

## 결정 (Decision)

**확장은 `play = { size, load, update, draw, keypressed, keyreleased, mousepressed, mousereleased, mousemoved }`(LÖVE 콜백 이름)를 둔다.
블록은 계속 `draw`를 그리고, 블록의 ▶ 단추(또는 `play` 동작)가 새 창을 열어 `play`를 실행한다.**

- 실행: 창마다 플레이 작업 스레드 하나가 확장 파일을 새로 읽어 자기 Lua 상태를 든다(블록 작업 스레드와 별개). 상태는 Lua(파일의
  `local`)에 있고 `load(args)`가 블록 인자로 시작한다. 창은 프레임마다 그 사이의 입력과 지난 시간(`dt`, 0.1초까지)을 보내고, 스레드는
  입력 콜백 → `update(dt)` → `draw(g)`를 돌아 모양을 돌려준다. 답을 기다리는 동안은 보내지 않는다. 호출마다 0.1초, 프레임마다 모양
  2천 개까지다.
- 창: 캔버스(`play.size`, 없으면 블록 크기)를 창 크기에 비율을 지켜 맞춘다. 키(gpui 키 이름, 누른 채로 반복은 보내지 않는다)와 마우스
  (캔버스 좌표, 단추 1·2·3)를 받는다. 비활성이면 시간을 멈추고(첫 그림은 그린다) 돌아오면 이어 간다. 오류가 나면 멈추고 창에 보인다.
  닫으면 스레드가 끝난다.
- 원고: 플레이는 원고에 아무것도 쓰지 않고 내보내기에 들어가지 않는다. 게임은 반환 표에 `export = false`를 두기를 권한다(ADR-0034).
- 여는 곳: `play`가 있는 블록의 캔버스 오른쪽 위 ▶, `click`의 `{ "play", args = … }` 동작(앞머리 `actions:`에 선언, 허락은 묻지 않는다).
- 스킬: `references/play.md`, 예제 게임 `dodge`(시험에서 300프레임을 입력과 함께 돌린다).

## 결과 (Consequences)

- (+): 에디터 입력·그리기와 섞이지 않고, 원고와 내보내기는 그대로다.
- (+): 블록과 같은 캔버스 API라 그림 지식을 그대로 쓴다.
- (-): `run_extension`은 플레이를 돌리지 못한다(블록 `draw`만 그린다).
- (-): 소리·이미지·텍스트 입력(IME)은 없다. 키 이름은 gpui를 따르므로 LÖVE와 조금 다르다(`enter`).
- (-): 프레임마다 작업 스레드를 왕복하고 창을 다시 그린다(창이 열려 활성인 동안만).
