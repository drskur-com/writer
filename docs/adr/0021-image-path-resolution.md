# ADR-0021: 이미지 상대 경로는 한 곳에서 찾고, `../`가 어긋난 경로도 위 폴더에서 다시 찾는다

- 상태: Proposed
- 날짜: 2026-10-22
- 관련: ADR-0007(이미지 속성), ADR-0008(에디터 이미지), ADR-0013(미리보기), ADR-0015(DOCX), ADR-0019·ADR-0020(그룹 간 이동), ADR-0022(새 이미지는 프로젝트 기준 경로) · `src/library/images.rs`, `src/export/epub.rs`, `src/export/docx.rs`, `src/app/book_preview/layout.rs`, `src/app/editor_image.rs`

## 배경 (Context)

이미지 경로(`![캡션](경로)`)를 파일로 바꾸는 규칙이 화면·내보내기마다 따로 있었다.

- 에디터·미리보기는 시트 폴더만 봤고, ePub·DOCX는 시트 폴더 → 프로젝트 폴더 → 첨부파일 그룹을 봤다.
- 앱은 이미지를 넣을 때 시트 폴더에서 본 상대 경로(`../../Extras/Attachments/<ULID>.jpeg`)를 썼다
  (ADR-0022부터는 프로젝트 기준 경로를 쓴다. 이 ADR의 다시 찾기는 옛 원고를 위해 남는다).
  그런데 시트나 그룹을 다른 폴더로 옮기면(ADR-0019·ADR-0020) `../` 깊이가 어긋난다.
  실제 라이브러리에서도 `본문/1장`의 시트가 `../Extras/…`(한 단계 모자란 경로)를 가리켜
  그림이 보이지 않았고, ePub은 그 상대 경로를 `src`에 그대로 써서 검증기에서 깨진 참조
  (RSC-007)가 됐다. ePub 리더는 그림 대신 오류를 보여 준다.
- ePub·DOCX는 찾지 못한 이미지를 각자 다르게 다뤘다. DOCX는 안내 문단을 넣고, ePub은 원문
  경로를 그대로 링크로 남겼다.

## 결정 (Decision)

**이미지 경로 해석은 `library::resolve_image_path`(`src/library/images.rs`) 하나를 쓰고,
`../`로 시작하는 경로는 `../`를 뗀 꼬리를 시트의 위 폴더들에서 한 번 더 찾는다.**

- 절대 경로(과 `file://`)는 그대로 쓰고, 웹 주소(`http://`·`https://`)는 파일로 찾지 않는다.
- 상대 경로 후보: ① 시트 폴더 → ② 프로젝트 폴더 → ③ `<Project>/Extras/Attachments`.
  프로젝트 폴더를 넘기지 않으면 시트 폴더가 든 라이브러리 프로젝트를 쓴다(ADR-0022).
- ①~③에서 못 찾고 경로가 `../`로 시작하면, `../`·`./`를 뗀 꼬리를 시트 폴더의 위 폴더들에서
  다시 찾는다. 위로는 프로젝트 폴더(모르면 `Projects/`·`Notes/` 바로 아래 폴더)까지만 올라간다.
  그룹 폴더에 `.writer.toml`이 꼭 있지는 않으므로, 메타 파일은 라이브러리 밖에서만 경계로 쓴다.
  그래서 그룹을 옮겨 깊이가 어긋난 경로도 같은 파일을 찾는다.
- 찾은 경로는 `..`를 푼 실제 경로로 돌려준다. 다르게 적은 경로라도 같은 파일이면 한 번만 넣는다.
- 못 찾은 이미지는 ePub에서 원문 경로를 `src`로 쓰지 않는다. 미리보기·DOCX와 같이
  `[이미지를 찾을 수 없음: 경로]` 안내 문단(`<p class="missing-image">`)으로 바꾼다.
- 찾은 파일은 ePub에 `images/img_NNNN.<확장자>`로 한 번만 넣고, 섹션(`text/…`)에서 본
  상대 경로(`../images/…`)로 가리킨다. 같은 파일을 여러 번 써도 한 번만 넣는다.

## 결과 (Consequences)

- (+): 에디터·미리보기·PDF·DOCX·ePub이 같은 그림을 본다. 규칙이 한 곳에 있다.
- (+): 시트·그룹을 옮긴 뒤에도 그림이 이어진다. Finder나 다른 도구에서 폴더를 옮긴 경우도 같다.
- (+): ePub이 존재하지 않는 경로를 가리키지 않아 검증기 오류와 깨진 그림이 사라진다.
- (-): 상대 경로가 실제로 틀려도 위 폴더에 꼬리가 똑같은 파일이 있으면 그것을 쓴다.
  꼬리 전체가 같아야 하므로 드물지만, 옮긴 뒤 경로를 고치지 않으면 원래 뜻과 달라질 수 있다.
- (-): 파일을 찾을 때 후보 경로를 몇 번 더 확인한다(이미지 수만큼의 파일 조회).

## 대안 (Alternatives)

| 대안 | 기각 사유 |
| --- | --- |
| 옮길 때 마크다운의 `../`를 다시 쓰기 | 사용자 글을 앱이 고치게 되고, 파일 이동·메타 저장과 함께 되돌리기(롤백)가 어려워진다. 이미 어긋난 원고도 고쳐 주지 못한다 |
| ePub 내보내기만 고치기 | 에디터·미리보기·DOCX는 여전히 그림을 못 찾아 화면마다 결과가 다르다 |
| 못 찾은 이미지를 ePub에서 조용히 빼기 | 독자는 그림이 있었는지조차 모른다. 미리보기·DOCX처럼 자리와 경로를 보여 주는 편이 낫다 |
| 이미지를 ePub에 넣지 않고 원래 경로를 그대로 두기 | ePub 안에는 그 경로가 없으므로 항상 깨진 참조가 된다 |
