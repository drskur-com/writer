# ADR-0047: 시스템 테마 4개는 바이너리에 두고, 라이브러리 `Themes/*.json`의 테마를 더한다

- 상태: Proposed
- 날짜: 2026-10-23
- 관련: ADR-0001(테마 색은 JSON이 단일 출처) · `src/theme.rs`, `themes/writer.json`, `src/settings.rs`, `resources/skills/theme/`

## 배경 (Context)

테마는 `themes/writer.json`의 두 개(Writer Light/Dark)뿐이었고, 메뉴로만 고를 수 있었다. 사용자는 터미널과 같은 팔레트(Gruvbox)처럼
자기 테마를 쓰고 싶어 하고, 어시스턴트에게 테마를 만들어 달라고 할 수도 있어야 한다. 만든 테마는 지울 수 있어야 하지만 기본 테마는
늘 남아 있어야 한다.

## 결정 (Decision)

**시스템 테마(Writer Light/Dark, Gruvbox Light/Dark)는 `themes/writer.json`에 넣어 바이너리에 둔다. 사용자 테마는 열린 라이브러리의
`Themes/<이름>.json`(gpui-component `ThemeSet` 스키마)에서 읽는다.**

- 테마 목록은 앱의 `ThemeStore`가 들고 있다. gpui-component `ThemeRegistry`에는 지우는 API가 없어 쓰지 않는다.
- 라이브러리를 열거나 폴더가 바뀔 때(폴더 감시의 다시 읽기) `Themes/`를 다시 읽는다. 내용이 같으면 아무것도 하지 않는다.
  시스템 테마나 앞 파일과 이름이 같은 테마, 읽지 못하는 파일은 건너뛴다. 서체·크기·모서리 값은 버리고 색만 쓴다.
- 고른 테마 이름은 `config.toml`의 `theme`에 남긴다. 라이브러리 테마가 없으면(다른 라이브러리) 같은 모드의 기본 테마를 보이되
  저장된 이름은 그대로 둬서, 그 라이브러리를 다시 열면 돌아온다. 시작할 때는 마지막 라이브러리의 테마를 먼저 읽는다.
- 설정 창 일반 페이지에 테마 선택을 둔다. 라이브러리 테마면 파일 보기·삭제(휴지통) 버튼을 보이고, 시스템 테마면 지울 수 없다고 적는다.
  삭제는 파일 단위다(라이트·다크 한 쌍이 한 파일에 있다).
- 라이트/다크 전환은 같은 계열(이름 끝 ` Light` ↔ ` Dark`)의 반대 모드 테마로, 없으면 기본 테마로 간다.
- 테마가 바뀌면 메인 창은 `Theme` 전역을 관찰해 메뉴의 체크와 에디터 장식을 맞춘다. 메뉴·단축키·설정 창·파일 변경이 모두 같은 길을 쓴다.
- 어시스턴트는 기존 `write_file`·`edit_file`로 `Themes/*.json`을 쓴다(승인 카드를 거친다). 쓰기 전에 JSON과 이름을 검사하고,
  `Themes/` 폴더는 첫 테마를 승인할 때 만든다. 형식과 색 키는 빌트인 스킬 `theme`이 알려 준다.

## 결과 (Consequences)

- (+): 테마를 더하는 데 새 도구가 필요 없다. 테마가 라이브러리와 함께 동기화된다. 사용자는 JSON을 직접 고쳐도 바로 보인다.
- (-): 라이브러리 테마는 그 라이브러리를 열었을 때만 보인다.
- (-): 빠진 색 키는 gpui-component 기본색으로 채워져 팔레트와 어긋날 수 있다(스킬이 모든 키를 쓰라고 한다).

## 대안 (Alternatives)

| 대안 | 기각 사유 |
| --- | --- |
| 앱 설정 폴더(`<config_dir>/Writer/themes/`)에 둔다 | 어시스턴트의 파일 도구는 라이브러리 안만 다룬다. 테마 전용 도구가 따로 필요하다 |
| `ThemeRegistry`에 등록한다 | 지우는 API가 없고, 레지스트리 관찰자가 활성 테마를 바꿔 끼운다 |
| 테마 하나당 파일 하나 | 라이트·다크 한 쌍을 나눠 관리해야 하고, 삭제·전환이 짝을 잃는다 |
