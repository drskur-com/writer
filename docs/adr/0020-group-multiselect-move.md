# ADR-0020: 그룹을 Shift로 여러 개 골라 다른 그룹의 하위로 끌어 옮긴다

- 상태: Proposed
- 날짜: 2026-10-22
- 관련: ADR-0005, ADR-0019 · `src/library/meta.rs`, `src/app/library_panel.rs`, `src/app/project_panel.rs`, `src/app/library_ops.rs`

## 배경 (Context)

ADR-0019는 시트 카드를 다른 그룹으로 옮기는 동작만 정했다. 사이드바의 그룹 줄은 시트를 받기만 했고,
그룹 자체를 다른 그룹의 하위로 옮기려면 Finder에서 폴더를 옮기거나 그룹을 다시 만들어야 했다.
그룹은 실제 폴더이고 하위 그룹은 폴더 안의 폴더이므로, 그룹 이동은 곧 폴더 이동이며
원래 부모와 대상 그룹의 `.writer.toml`에 있는 `groups` 순서도 함께 맞춰야 한다.

## 결정 (Decision)

**그룹 줄을 Shift+클릭으로 넓혀 여러 개 고를 수 있고, 고른 그룹 중 하나를 같은 범위의 다른 그룹 줄에
끌어다 놓으면 그 그룹들의 폴더를 대상 그룹 아래로 옮긴다.**

- Shift+클릭은 마지막으로 그냥 누른 그룹(기준 그룹)부터 누른 그룹까지, 지금 화면에 보이는 줄 순서로 넓힌다.
  기준 그룹은 바꾸지 않으므로 오른쪽 시트 목록은 기준 그룹을 그대로 보여 준다.
- 넓히기는 같은 이동 범위 안에서만 한다. 범위는 메모 그룹, 프로젝트의 원고 그룹, 프로젝트의 추가자료 그룹,
  프로젝트 자신으로 나뉜다.
- 끌 수 있는 것은 메모 그룹·원고 그룹·추가자료 그룹이다. `Projects/` 바로 아래의 프로젝트는 끌지 않는다.
- 놓을 수 있는 대상은 같은 범위의 그룹이다. 원고 그룹을 추가자료 그룹으로, 또는 그 반대로 옮기지 않는다.
- 여러 그룹을 고른 채 그중 하나를 끌면 고른 그룹을 화면 순서대로 함께 옮긴다. 부모와 자식이 모두 선택에
  들어 있으면 부모만 옮긴다(자식 폴더는 부모를 따라간다).
- 자기 자신, 자기 하위, 자기 조상으로는 놓을 수 없다(순환·제자리 이동 방지). 끌고 있는 그룹과 관계된
  대상은 강조하지 않는다.
- 대상 그룹에 같은 이름의 폴더가 있으면 `이름 2`처럼 비어 있는 이름으로 옮긴다.
- 앱이 이름으로 찾는 기본 추가자료 그룹(템플릿·첨부파일)은 옮기지 않는다.
- 폴더 이동 뒤 원래 부모의 `groups`에서 빼고 대상 그룹의 `groups` 맨 뒤에 붙인다. 메타 쓰기가 실패하면
  폴더와 두 메타 파일을 원래대로 되돌린다.
- 열린 시트가 옮긴 그룹 안에 있으면 먼저 저장하고 새 경로로 편집을 이어 간다. 선택·펼침 상태의 경로도
  새 위치로 바꾸고, 옮긴 그룹이 보이도록 대상 그룹을 펼친다.

## 결과 (Consequences)

- (+): Finder를 열지 않고 사이드바에서 그룹을 정리하고 하위로 묶을 수 있다.
- (+): 여러 그룹을 한 번에 옮겨도 순서와 열린 편집 상태가 유지된다.
- (+): 실패 시 폴더와 메타가 원래 자리로 돌아가 라이브러리가 반쯤 옮겨진 채 남지 않는다.
- (-): 원고 그룹과 추가자료 그룹 사이의 이동은 막혀 있어, 빌드 대상 여부를 바꾸려면 따로 만들어야 한다.
- (-): 그룹 사이 순서를 바꾸는 끌기(같은 부모 안 재정렬)는 아직 없다.

## 대안 (Alternatives)

| 대안 | 기각 사유 |
| --- | --- |
| Ctrl/Cmd+클릭으로 하나씩 더 고른다 | 요청은 Shift 범위 선택이고, 기준 그룹이 분명해 범위 계산이 단순하다 |
| 그룹을 끌어 프로젝트 제목에 놓아 최상위로 보낸다 | 이번 결정은 “다른 그룹의 하위로”만 다룬다. 최상위 이동은 별도 규칙이 필요하다 |
| 원고·추가자료 그룹을 자유롭게 섞어 옮긴다 | 빌드 대상 여부가 조용히 바뀌어 사용자가 결과를 예측하기 어렵다 |
| 메타에 소속만 적고 폴더는 두다 | 그룹 폴더가 소속을 정하는 기존 구조와 Finder·동기화가 어긋난다 |
| 이름이 겹치면 옮기지 않는다 | 같은 이름의 그룹을 합치려는 것이 아니라 나란히 두려는 경우가 많다 |
